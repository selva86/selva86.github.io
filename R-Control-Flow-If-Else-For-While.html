R Control Flow: if/else, for, and while — Stop Avoiding Loops

Control flow in R directs the order of execution using conditionals (if/else) to make decisions and loops (for, while) to repeat actions — the building blocks of any non-trivial program.

Every useful R script needs to make decisions and repeat tasks. Should you classify this patient as high-risk? Process each file in a folder? Keep iterating until convergence? Control flow handles all of this.

This tutorial covers every control flow tool in R with real examples you can run and modify. You'll also learn when to replace loops with faster vectorized alternatives.

Every code block below is interactive. Click Run to execute, edit to experiment, and Reset to restore the original.

if/else: Making Decisions

The if statement runs code only when a condition is TRUE.

R
temperature <- 38.5 if (temperature > 37.5) { cat("Fever detected:", temperature, "°C\n") } # Nothing prints if condition is FALSE if (temperature > 40) { cat("Critical temperature!\n") }

    

  





The condition inside if() must evaluate to a single TRUE or FALSE. R checks it, and if TRUE, runs the code inside the curly braces. If FALSE, it skips that block entirely.



if/else



Add else to handle the FALSE case.




  

    

      R
      

        
        
      

    

    
score <- 72

if (score >= 60) {
  cat("Result: PASS\n")
} else {
  cat("Result: FAIL\n")
}

cat("Score was:", score)

    

    

  





Important: The else must appear on the same line as the closing brace }. Writing else on a new line causes an error in R.



if/else if/else Chains



Use else if to check multiple conditions in sequence. R stops at the first TRUE condition.




  

    

      R
      

        
        
      

    

    
bmi <- 27.3

if (bmi < 18.5) {
  category <- "Underweight"
} else if (bmi < 25) {
  category <- "Normal"
} else if (bmi < 30) {
  category <- "Overweight"
} else {
  category <- "Obese"
}

cat("BMI:", bmi, "-> Category:", category, "\n")

    

    

  





Order matters. R checks each condition from top to bottom and runs the first matching block. Put the most specific conditions first.



if/else as an Expression



In R, if/else returns a value. You can assign the result directly to a variable.




  

    

      R
      

        
        
      

    

    
age <- 20

# if/else returns a value — assign it directly
status <- if (age >= 18) "adult" else "minor"
cat("Age", age, "->", status, "\n")

# Useful for setting defaults
user_input <- NULL
value <- if (!is.null(user_input)) user_input else "default"
cat("Value:", value, "\n")

    

    

  





This pattern is clean for simple two-way assignments. For anything more complex, use the multi-line form with braces.



ifelse(): The Vectorized Conditional



The if statement checks one value. ifelse() checks an entire vector at once.




  

    

      R
      

        
        
      

    

    
scores <- c(85, 42, 91, 58, 73, 36)

# ifelse() works on the whole vector
results <- ifelse(scores >= 60, "Pass", "Fail")
results

# Compare: if() would fail on a vector
# if (scores >= 60) "Pass" else "Fail"  # Error! condition has length > 1

    

    

  





Use if for single values (inside functions, controlling script flow). Use ifelse() for vectors (classifying data, creating new columns).

Nested ifelse() for Multiple Categories




  

    

      R
      

        
        
      

    

    
scores <- c(95, 82, 67, 54, 41)

# Nested ifelse for letter grades
grades <- ifelse(scores >= 90, "A",
           ifelse(scores >= 80, "B",
             ifelse(scores >= 70, "C",
               ifelse(scores >= 60, "D", "F"))))

data.frame(score = scores, grade = grades)

    

    

  





Nested ifelse() works but gets hard to read. For many categories, consider cut() or dplyr::case_when() instead.



for Loops



A for loop repeats code for each element in a sequence.




  

    

      R
      

        
        
      

    

    
# Loop over a vector
fruits <- c("apple", "banana", "cherry")

for (fruit in fruits) {
  cat("I like", fruit, "\n")
}

    

    

  





The loop variable (fruit) takes each value in the vector, one at a time. After the loop, it holds the last value.



Looping with Index



Use seq_along() when you need the position as well as the value.




  

    

      R
      

        
        
      

    

    
cities <- c("London", "Paris", "Tokyo", "Sydney")
populations <- c(8.9, 2.2, 13.9, 5.3)

for (i in seq_along(cities)) {
  cat(i, ".", cities[i], "-", populations[i], "million\n")
}

    

    

  





Use seq_along(x) instead of 1:length(x). If x is empty, 1:length(x) gives 1:0 which is c(1, 0) — a bug. seq_along(x) correctly returns an empty sequence.



Collecting Results in a Loop



Pre-allocate a results vector before the loop. Never grow a vector inside a loop with c() — it's extremely slow.




  

    

      R
      

        
        
      

    

    
# Good: pre-allocate the result vector
n <- 10
squares <- numeric(n)  # Creates c(0, 0, 0, ..., 0)

for (i in 1:n) {
  squares[i] <- i^2
}

squares

# Bad (slow): growing a vector
# result <- c()
# for (i in 1:n) result <- c(result, i^2)  # Copies entire vector each time!

    

    

  





Pre-allocation matters for performance. Growing a vector with c() inside a loop copies the entire vector every iteration. For 10 items it's fine. For 100,000 items, it's catastrophically slow.



Looping Over List Elements




  

    

      R
      

        
        
      

    

    
# Loop over a named list
config <- list(host = "localhost", port = 8080, debug = TRUE)

for (key in names(config)) {
  cat(key, "=", as.character(config[[key]]), "\n")
}

    

    

  





When looping over a list by name, use config[[key]] (double brackets) to get the value. Single brackets would return a sub-list.



while Loops



A while loop repeats as long as a condition stays TRUE. Use it when you don't know how many iterations you need.




  

    

      R
      

        
        
      

    

    
# Simulate compound interest: how many years to double your money?
balance <- 1000
rate <- 0.07
target <- 2000
years <- 0

while (balance < target) {
  balance <- balance * (1 + rate)
  years <- years + 1
}

cat("Years to double:", years, "\n")
cat("Final balance: $", round(balance, 2), "\n")

    

    

  





The condition is checked before each iteration. If it starts as FALSE, the loop body never runs. Always make sure the condition will eventually become FALSE, or your loop runs forever.



Convergence Example




  

    

      R
      

        
        
      

    

    
# Newton's method to find sqrt(25)
guess <- 10
tolerance <- 0.0001
iteration <- 0

while (abs(guess^2 - 25) > tolerance) {
  guess <- (guess + 25 / guess) / 2
  iteration <- iteration + 1
  cat("Iteration", iteration, ": guess =", guess, "\n")
}

cat("\nFinal answer:", guess, "\n")
cat("Actual sqrt(25):", sqrt(25), "\n")

    

    

  





This is the classic use case for while: iterate until a condition is met (convergence, threshold, target). You can't use a for loop because you don't know in advance how many steps it will take.



next and break: Loop Control



next skips to the next iteration. break exits the loop entirely.




  

    

      R
      

        
        
      

    

    
# next: skip odd numbers
cat("Even numbers from 1-10: ")
for (i in 1:10) {
  if (i %% 2 != 0) next  # Skip odd
  cat(i, "")
}

# break: stop at first negative
cat("\n\nProcessing until negative:\n")
values <- c(3, 7, 2, -1, 5, 8)
for (val in values) {
  if (val < 0) {
    cat("Negative found! Stopping.\n")
    break
  }
  cat("Processed:", val, "\n")
}

    

    

  





next is like "skip this one and keep going." break is like "stop the loop right now." Both work in for and while loops.



Nested Loops



Loops inside loops. The inner loop runs completely for each iteration of the outer loop.




  

    

      R
      

        
        
      

    

    
# Multiplication table
cat("   ")
for (j in 1:5) cat(sprintf("%4d", j))
cat("\n   ", rep("----", 5), "\n")

for (i in 1:5) {
  cat(sprintf("%2d|", i))
  for (j in 1:5) {
    cat(sprintf("%4d", i * j))
  }
  cat("\n")
}

    

    

  





Nested loops are useful for matrices, grids, and pairwise comparisons. But they can be slow — if the inner loop runs 1000 times and the outer runs 1000 times, that's 1,000,000 iterations. Look for vectorized alternatives when possible.



When to Use Vectorized Alternatives



R is designed for vectorized operations. Many tasks that need loops in other languages can be done without loops in R — and the vectorized version is almost always faster and cleaner.




  

    

      R
      

        
        
      

    

    
x <- c(4, 9, 16, 25, 36)

# Loop version (avoid this)
result_loop <- numeric(length(x))
for (i in seq_along(x)) {
  result_loop[i] <- sqrt(x[i])
}

# Vectorized version (prefer this)
result_vec <- sqrt(x)

cat("Loop result: ", result_loop, "\n")
cat("Vector result:", result_vec, "\n")
cat("Same?", all.equal(result_loop, result_vec), "\n")

    

    

  





The vectorized version is shorter, clearer, and faster. Here's a decision guide:






TaskUse Loop?Vectorized Alternative




Apply function to each elementNosapply(), vapply()


Classify values into categoriesNoifelse(), cut()


Cumulative operationsNocumsum(), cumprod()


Filter rowsNoLogical indexing, subset()


Each step depends on previousYesNo good alternative


Iterate until convergenceYesNo good alternative


Side effects (print, write files)YesNo good alternative






The apply Family: Brief Introduction




  

    

      R
      

        
        
      

    

    
# sapply: apply to each element, simplify result
sapply(1:5, function(x) x^2)

# lapply: same but returns a list
lapply(c("hello", "world"), toupper)

# vapply: like sapply but you specify the return type (safer)
vapply(1:5, function(x) x^2, numeric(1))

    

    

  





The apply family replaces many common loop patterns. Learn more about them in the R Lists tutorial where we cover lapply() and sapply() in depth.



Putting It All Together: A Real Example



Here's a practical script that combines all the control flow tools. It processes student records and generates a grade report.




  

    

      R
      

        
        
      

    

    
# Student grade report generator
students <- data.frame(
  name = c("Alice", "Bob", "Carol", "Dave", "Eve"),
  midterm = c(88, 45, 92, 67, 78),
  final = c(91, 52, 88, 71, 82),
  stringsAsFactors = FALSE
)

cat("========== GRADE REPORT ==========\n\n")

pass_count <- 0

for (i in 1:nrow(students)) {
  avg <- (students$midterm[i] + students$final[i]) / 2

  # Assign letter grade
  if (avg >= 90) {
    grade <- "A"
  } else if (avg >= 80) {
    grade <- "B"
  } else if (avg >= 70) {
    grade <- "C"
  } else if (avg >= 60) {
    grade <- "D"
  } else {
    grade <- "F"
  }

  # Track passing students
  if (grade != "F") pass_count <- pass_count + 1

  # Flag improvement or decline
  trend <- if (students$final[i] > students$midterm[i]) "improved" else "declined"

  cat(sprintf("%-6s | Avg: %5.1f | Grade: %s | %s\n",
              students$name[i], avg, grade, trend))
}

cat("\n==================================\n")
cat("Pass rate:", pass_count, "/", nrow(students),
    "(", round(100 * pass_count / nrow(students)), "%)\n")

    

    

  





This script uses for to iterate over rows, if/else if/else to assign grades, and if as an expression to determine the trend. Try changing the scores and see how the report updates.

FAQ



Why does R warn "the condition has length > 1" with if?


The if statement expects a single TRUE or FALSE. If you pass a vector like if (c(TRUE, FALSE)), R uses only the first element and warns you. Use ifelse() for vectors, or any()/all() to reduce a vector to a single logical.



Are for loops slow in R?


For loops are slower than vectorized operations, but not as slow as people think. A well-written loop with pre-allocated results runs in milliseconds for thousands of iterations. The real performance killer is growing objects inside a loop with c() or rbind().



What's the difference between ifelse() and dplyr's if_else()?


dplyr::if_else() is stricter: it requires both outcomes to have the same type and preserves attributes. ifelse() silently coerces types and can drop attributes (like dates becoming numbers). Use if_else() in dplyr pipelines for safety.



Can I use switch() instead of long if/else chains?


Yes. switch() matches a value against named options: switch(x, "a" = 1, "b" = 2, "c" = 3). It's cleaner than long if/else chains when you're matching exact values rather than ranges.



How do I avoid infinite while loops?


Always ensure the loop condition will eventually become FALSE. Add a safety counter: max_iter <- 1000; iter <- 0 and include if (iter >= max_iter) break inside the loop. This prevents runaway execution if your logic has a bug.

## C. Outline

### Lead paragraph
"'Model failed to converge' in lme4 means the optimiser stopped at a point where its stopping criterion — the gradient of the log-likelihood — is still larger than the tolerance it expects. The fit is returned, but its coefficients may be unreliable. Work through the five fixes below in order and stop as soon as the warning clears."

### H2 1 — Why does lme4 say the model failed to converge?
Opening prose (~75 words): The warning is a gradient-tolerance check. Default tolerance is 0.002. When a predictor sits on a scale that is orders of magnitude larger or smaller than others, the optimiser's search steps become numerically incomparable to the curvature they are trying to measure, and the gradient never drops below tolerance. Reproduce that with a single simulated dataset and watch the warning disappear after one `scale()` call.

Code block 1 (PAYOFF):
- Load lme4
- Simulate 200 rows, 20 groups, one predictor `x_raw ~ N(1e5, 5e4)`
- Fit `lmer(y ~ x_raw + (1|group))` → triggers warning
- Rescale → refit → no warning
- Print final gradient before/after via `m@optinfo$derivs$gradient`

Interpretation (2-4 sentences): final gradient dropped from ~0.003 to ~4e-8, same data, only difference is one call to `scale()`. Numerical step sizes now match the curvature the optimiser is trying to measure.

[KEY INSIGHT] callout: the warning is a gradient tolerance check, not an error — your goal is to move the gradient clearly into the "accept" region.

Inline exercise 1: use `scale()` inside the formula and report the final gradient.

### H2 2 — Fix 1: How should you rescale predictors?
Opening (~60 words): `scale()` centers at 0 and divides by SD, putting every predictor on the same unit of "one SD". Why this matters for mixed models: the random-effect variance component sits on the same units as the fixed effect; unscaled predictors make variance components numerically tiny or huge. Do this for every numeric predictor before the first fit.

Code block 2:
- Simulate a second dataset with 3 numeric predictors on wildly different scales
- `mutate(across(where(is.numeric), ~ as.numeric(scale(.))))`
- Fit and show converged summary (variance components, fixed effects)

Interpretation: one line per coefficient, emphasise that converged fit is trustworthy only after scaling.

[TIP] callout: keep the centering/scaling params so you can back-transform for interpretation.

Inline exercise 2: scale only the numeric columns of a supplied `df` and report the final gradient.

### H2 3 — Fix 2: When should you simplify the random-effects structure?
Opening (~70 words): Barr et al. (2013) recommended "keep it maximal" — random slopes for every within-subject factor. Matuschek et al. (2017) showed this often overparameterises the model and kills convergence on real datasets. The fix: start with random intercepts only, add correlated slopes if convergence holds, drop correlations if it doesn't. Model comparison with anova() tells you whether the extra variance component earns its keep.

Code block 3:
- Simulate crossed-random-effects data (subject x item), 30 subjects, 20 items
- Fit `(1 + cond | subject) + (1 + cond | item)` → warning
- Refit `(1 | subject) + (1 | item)` → converges
- `anova()` comparison

Interpretation: random slopes contributed effectively zero variance; removing them keeps the fit identifiable.

[WARNING] callout: don't drop random slopes you theoretically need — try uncorrelated (`||`) specification first.

Inline exercise 3: drop the random slope from `(1 + x | group)` and refit.

### H2 4 — Fix 3: How do you switch or combine optimisers with allFit()?
Opening (~65 words): lme4 ships multiple optimisers (bobyqa, Nelder_Mead, nlminbwrap, nloptwrap variants). Different optimisers take different paths through the likelihood surface; one may get stuck where another doesn't. `allFit()` refits the same model with every optimiser so you can compare gradients and parameter estimates. If they all land on the same coefficients, the warning is cosmetic.

Code block 4:
- Use the slightly-above-tolerance fit from H2 1 or H2 3
- Call `allFit(m_tight)` → summary of gradients and log-likelihoods across optimisers
- Pick the one with the smallest gradient and use it via `lmerControl(optimizer = ...)`

Interpretation: when the deviances are identical to 4 decimal places, the warning is about the gradient check, not about estimate disagreement.

[NOTE] callout: allFit() is slow — only run it once you've tried Fix 1 and Fix 2.

Inline exercise 4: extract the optimiser with the smallest final gradient from an allFit() output.

### H2 5 — Fix 4: How do you detect and handle a singular fit?
Opening (~60 words): A singular fit means at least one variance component is estimated at its boundary — exactly zero, or a correlation of ±1. lme4 detects this with `isSingular()`. A singular fit is not the same as a convergence failure, but the two often appear together because the optimiser is trying to optimise a parameter that has no information in it.

Code block 5:
- Simulate data with no real group-level effect
- Fit `(1 | group)` → `isSingular(m) == TRUE`
- Check `VarCorr(m)` → group variance is ~0
- Refit without the random effect or use a fixed effect instead

Interpretation: the warning and the singularity share a cause; dropping the redundant random term fixes both.

Inline exercise 5: call `isSingular()` on a supplied fit and print the variance components.

### H2 6 — Fix 5: When should you increase iterations or widen tolerance?
Opening (~70 words): This is the last resort, and only useful when Fixes 1–4 got you close. If the gradient is just above tolerance and all optimisers agree on the estimates, one honest move is raising `optCtrl = list(maxfun = 200000)` so bobyqa has more budget to polish the answer. Never just widen the tolerance — that hides the warning without fixing anything.

Code block 6:
- Take the near-convergence fit
- Refit with `lmerControl(optimizer = "bobyqa", optCtrl = list(maxfun = 2e5))`
- Show final gradient now below tolerance

[WARNING] callout: widening `check.conv.grad` tolerance is silencing a smoke alarm, not a fix.

Inline exercise 6: refit a model with `maxfun = 100000`.

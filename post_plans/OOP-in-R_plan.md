## C. Full Section Outline

### Lead Paragraph
R has four object-oriented programming systems — S3, S4, R5 (Reference Classes), and R6 — each with different trade-offs around formality, mutability, and ease of use. Three questions are all you need to pick the right one for your project.

### H2-1: What are R's four OOP systems and why do they exist?
- **Opening prose (≤80 words):** R evolved its OOP systems over decades. S3 arrived in the early 1990s as a lightweight convention. S4 added formal contracts in R 1.4. R5 (Reference Classes) brought mutable objects in R 2.12. R6, a CRAN package, refined the mutable approach with a cleaner API. Let's see all four at work on the same task — creating a simple "dog" object and asking for its description.
- **Code block 1 (PAYOFF):** Create an S3 "dog" object, define a `describe()` generic and method, call it — visible output showing polymorphism at work.
- **Theory:** Two OOP paradigms in R — functional (S3/S4: methods belong to generics) vs encapsulated (R5/R6: methods belong to objects). Analogy: functional OOP is like a restaurant where the waiter (generic) decides who handles your order based on cuisine; encapsulated OOP is like a food truck where the truck (object) does everything itself.
- **Diagram:** Figure 1 — Functional vs Encapsulated OOP (placed after the theory, NOT before code block 1)
- **Callout:** KEY INSIGHT — Functional vs encapsulated is the fundamental divide
- **Inline exercise:** Create an S3 "cat" object with name and lives fields, write a describe.cat method

### H2-2: How does S3 work?
- **Theory:** Class = a character attribute, constructor = a regular function, methods = naming convention (generic.class), inheritance via class vector, dispatch via UseMethod()
- **Code block 2:** Full S3 class — constructor with validation, generic, method, print method, inheritance (show a "puppy" inheriting from "dog")
- **Code block 3:** Method dispatch — show how UseMethod() walks the class vector, demonstrate with sloop::s3_dispatch() if available, otherwise show is() and inherits()
- **Callout:** TIP — Always write a constructor function, never use structure() or class<-() directly
- **Callout:** WARNING — S3 has no built-in type checking — anyone can create an invalid object
- **Inline exercise:** Create an S3 "book" class with title, author, pages; write a summary.book method

### H2-3: How does S4 add formal structure?
- **Theory:** setClass() with slots, new() constructor, setGeneric()/setMethod(), validity checks, isVirtualClass, multiple inheritance, multiple dispatch
- **Code block 4:** Define an S4 "Animal" class with typed slots, validity function, show method
- **Code block 5:** S4 inheritance — "Dog" extends "Animal" with extra slot, demonstrate slot access with @, show validity rejection
- **Callout:** NOTE — S4 is the standard in Bioconductor; if you contribute to bioinformatics packages, learn S4
- **Callout:** KEY INSIGHT — S4's validity function runs automatically on object creation — S3 can't do this
- **Inline exercise:** Create an S4 "Rectangle" class with width/height slots (both numeric), add a validity check that both must be positive, write an area() method

### H2-4: What are R5 reference classes?
- **Theory:** setRefClass() creates mutable objects, fields = typed slots, methods live inside the class, $copy() for deep copy, reference semantics (like Python/Java), part of base R methods package
- **Code block 6:** R5 BankAccount — fields (balance), methods (deposit, withdraw, show), demonstrate mutability
- **Callout:** WARNING — Reference semantics mean assignment doesn't copy — changes affect all references
- **Code block 7:** Show the reference gotcha: assign account to a new variable, modify one, both change
- **Inline exercise:** Create an R5 "Counter" class with a count field, increment() and reset() methods

### H2-5: How does R6 improve on reference classes?
- **Theory:** R6Class() from the R6 package, public/private separation, active bindings, method chaining, no S4 dependency (lighter), initialize() constructor, clone() for deep copy
- **Code block 8:** R6 BankAccount — public (deposit, withdraw, get_balance), private (balance), active binding (balance_usd), demonstrate
- **Code block 9:** R6 inheritance and method chaining — SavingsAccount extends BankAccount, add interest method, chain calls
- **Callout:** TIP — Use private fields + active bindings to enforce encapsulation — no direct $balance access
- **Callout:** KEY INSIGHT — R6 objects behave like Python/Java objects — if you come from those languages, R6 will feel natural
- **Inline exercise:** Create an R6 "Logger" class with private messages list, public log() and show_all() methods

### H2-6: Which OOP system should you choose?
- **The 3-question decision tree:**
  - Q1: Does your object need mutable state (modify in place)? No → Q2a. Yes → Q2b.
  - Q2a: Do you need formal validation and multiple dispatch? No → S3. Yes → S4.
  - Q2b: Can your project depend on an external package? Yes → R6. No → R5.

- **Callout:** TIP — When in doubt, start with S3. You can always refactor to S4 or R6 later.

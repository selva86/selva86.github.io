## C. Full Section Outline

### Lead Paragraph
S3 is R's original object system — the one that powers `print()`, `summary()`, and `plot()` on every object you touch. It has no formal class declarations, no schema, no boilerplate. You build a class by setting one attribute on a list, and you teach R new tricks by naming a function the right way.

### First H2 Opening (≤80 words)
Every time you call `print()` on a data frame and get a table, or call `summary()` on a linear model and get coefficients, S3 dispatch is running behind the scenes. Let's see that mechanism in action by building a custom class from scratch.

### Core H2 Sections

#### H2-1: What is S3 and how does it work?
- **Theory:** S3 = informal OOP. No class definition keyword. A class is just a character string stored in the `class` attribute. R's dispatch looks for `generic.class()`.
- **Code blocks:**
  1. (PAYOFF) Create a "pet" object from a list, assign class, call print() — show custom vs default behavior. Show class() and inherits().
- **Callout:** KEY INSIGHT — S3 has no enforcement; the convention IS the system.
- **Inline exercise:** Create a "book" object with title/author/pages, assign class, check with class() and inherits().

#### H2-2: How do you create an S3 class with a constructor?
- **Theory:** Raw class assignment is fragile. Constructor functions (new_classname) ensure consistent structure. Show structure() vs class<-() approaches.
- **Code blocks:**
  2. Constructor function new_pet() using structure()
  3. Bad object creation without constructor (show the problem)
- **Callout:** TIP — Name constructors new_classname() by convention.
- **Inline exercise:** Write a new_book() constructor.

#### H2-3: How does S3 method dispatch find the right function?
- **Theory:** When you call generic(obj), R pastes generic.class and looks for that function. Fallback to generic.default. UseMethod() is the engine.
- **Code blocks:**
  4. Define print.pet() and summary.pet() — show dispatch in action
  5. Show what methods() reveals for print, summary
- **Diagram:** S3-Classes-in-R-method-dispatch.webp (Figure 1)
- **Callout:** WARNING — The dot in print.pet is not a namespace separator; avoid dots in class names.
- **Inline exercise:** Write a format.book() method that returns a citation string.

#### H2-4: How do you write your own generic function?
- **Theory:** A generic is just a function that calls UseMethod("name"). Then you write name.class() methods. Default method as fallback.
- **Code blocks:**
  6. Create speak() generic with UseMethod(), then speak.pet() and speak.default()
  7. Show dispatch on different classes
- **Callout:** NOTE — You rarely need custom generics. Most of the time, you add methods to existing generics like print, summary, plot.
- **Inline exercise:** Write a describe() generic + describe.book() method.

#### H2-5: How does S3 inheritance work?
- **Theory:** Class attribute is a character vector. R walks left-to-right looking for methods. NextMethod() delegates to the parent. Subclasses are created by prepending to the class vector.
- **Code blocks:**
  8. Create dog and cat inheriting from pet, with class = c("dog", "pet")
  9. Show speak.dog(), speak.cat(), and fallback to speak.pet()
  10. Demonstrate NextMethod() for print.dog() calling print.pet()
- **Diagram:** S3-Classes-in-R-inheritance-chain.webp (Figure 2)
- **Callout:** KEY INSIGHT — Inheritance in S3 is just the order of names in the class vector. No formal "extends" keyword.
- **Inline exercise:** Create a "textbook" subclass of "book" that adds an edition field.

#### H2-6: What are best practices for production S3 code?
- **Theory:** The constructor-validator-helper pattern from Advanced R. Constructor builds, validator checks invariants, helper provides user-friendly interface.
- **Code blocks:**
  11. Full pattern: new_pet() (constructor) + validate_pet() (validator) + pet() (helper)
  12. Show validator catching bad input
- **Diagram:** S3-Classes-in-R-constructor-pattern.webp (Figure 3)
- **Callout:** TIP — Always validate in the helper, not the constructor. Constructors assume correct input for speed.
- **Inline exercise:** Write validate_book() that checks pages > 0 and title is non-empty.

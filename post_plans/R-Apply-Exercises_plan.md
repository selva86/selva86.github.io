**Theory:** vapply() is the type-safe version of sapply(). You specify the expected return type and length. If the result doesn't match, R throws an error instead of silently returning the wrong shape. This makes vapply() the professional choice for scripts and packages.

### H2 9: Summary

Table format:

| Function | Input | MARGIN? | Returns | Best For |
|----------|-------|---------|---------|----------|
| apply() | matrix/df | Yes (1=row, 2=col) | vector/matrix | Row/column operations |
| lapply() | list/vector | No | list | Safe iteration, always a list |
| sapply() | list/vector | No | vector/matrix (tries) | Quick interactive use |
| vapply() | list/vector | No | vector/matrix (typed) | Production code, type safety |
| tapply() | vector + factor | No | array | Group statistics |
| mapply() | multiple vectors | No | vector/matrix/list | Parallel iteration |

Key takeaways as bullets:
- Use lapply() as your default — lists are predictable
- Use vapply() in scripts/packages — the type contract catches bugs
- Use apply() only on matrices/data frames with MARGIN
- Use tapply() for quick group stats; switch to dplyr for complex pipelines
- Use mapply()/Map() when iterating over parallel inputs

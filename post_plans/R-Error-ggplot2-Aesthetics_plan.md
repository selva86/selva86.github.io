## C. Full section outline

### Lead paragraph

> `Error: Aesthetics must be either length 1 or the same as the data` fires whenever a variable you pass into `aes()` doesn't have exactly 1 value (a constant) or exactly `nrow(data)` values. The fix is almost always to attach the variable to the data frame as a column first, then map the column name inside `aes()`.

### Core H2 #1 — "What does 'Aesthetics must be length 1 or same as data' actually mean?"

**Opening prose (~70 words):** State the rule directly. ggplot2 maps aesthetics row-by-row, so every aesthetic must have exactly one value per row — or exactly one value total that gets recycled. Any other length is ambiguous and ggplot2 refuses to guess. The error message tells you which aesthetic broke (colour, fill, size).

**Code block 1 — the payoff (reproduction + fix):**
- Create tiny data frame (5 rows)
- Show broken call with commented `# Error: Aesthetics must be either length 1 or the same as the data (5): colour` in an inline `#>` comment
- Show working version that attaches the column to the data frame and maps it
- Run the working plot with `print(p)` so readers see ggplot2 actually rendering inside WebR

**Interpretation:** Point out that the `(5)` in the error message is the row count, and `colour` is the offending aesthetic — both clues are in the message itself.

**Inline Try it:** Given a 4-row data frame `ex_df` and a 2-element `ex_sizes` vector, fix the mapping.

### Core H2 #2 — "How do you fix a standalone vector that has the wrong length?"

**Opening:** Cause 1 — the commonest source. You define a helper vector outside the data frame, then try to map it directly.

**Code block 2:** `df` with 5 rows, `my_colors` with 3 values, show the mismatch via `length()` and `nrow()`. Fix by padding or (better) attaching as a column, then map by name.

**Callout [TIP]:** Prefer column-mapping over vector-mapping even when lengths match — it keeps data and aesthetics in sync when you filter.

**Inline Try it:** Fix a `highlight` vector of length 3 for a 6-row `ex_scores` data frame.

### Core H2 #3 — "How do you plot summary statistics next to raw data?"

**Opening:** Cause 2 — you compute group means and try to layer them on a raw-data plot. The summary has one row per group, the raw data has many.

**Code block 3:** `mtcars` grouped mean of mpg by cyl → two ways to fix: (a) `dplyr::mutate(group_by(...))` to attach group means to every raw row, (b) use the summary as a separate layer with its own `data =`.

**Callout [KEY INSIGHT]:** Aesthetic mapping operates on whatever data frame is in scope for the current layer — summaries belong in their own layer, not mixed into the parent aes.

**Inline Try it:** Attach `mean(mpg)` per group back to a full `ex_mtcars` copy.

### Core H2 #4 — "How do you combine layers from different data frames?"

**Opening:** Cause 3 — `geom_text` or `geom_point` inherits the parent `aes()` by default, so if the annotation data frame has a different row count the inherited aesthetic breaks.

**Code block 4:** Main scatter + annotation layer. Show the broken inherited version, then the fix: pass `data =` and `inherit.aes = FALSE`.

**Callout [WARNING]:** Forgetting `inherit.aes = FALSE` is the single most common reason multi-layer plots break — especially when the new layer's data doesn't even have the inherited column.

**Inline Try it:** Add a 2-row label layer to a scatter of 10 points.

### Core H2 #5 — "Why do lingering factor levels still cause length errors?"

**Opening:** Cause 4 — filtering drops rows but factor levels persist. A manual colour scale expecting 3 levels then receives 4 (or vice versa) and ggplot2 complains about a length mismatch.

**Code block 5:** Factor with 3 levels (`A`, `B`, `C`) → filter to just `A`/`B` → `droplevels()` → re-plot cleanly.

**Inline Try it:** Apply `droplevels()` to `ex_sub` and verify level count.

## C. Full Section Outline

### Lead sentence (`<p class="lead">`)

ggplot2 throws `object 'X' not found` when a name inside `aes()` does not exist as a column in the supplied data frame and also cannot be found in the calling environment. The fix hinges on one question: did you mean a data frame column (use a bare name or `.data[[var]]`) or an outside R value (pass it outside `aes()`)?

### Core H2-1: Why does ggplot2 say "object not found" inside aes()?

**Opening prose (~80 words, written out verbatim):**
`aes()` uses data masking. It first looks for every bare name in the data frame you passed to `ggplot()`, then in the calling environment. If the name is in neither, R raises `object 'X' not found`. Almost every instance is one of three root causes: a column name typo, a missing `data` argument, or a string variable that ggplot2 treats as a literal column name. Let's start with a working plot so you can see what a correct lookup looks like.

**Code block 1 (PAYOFF):** Load ggplot2, build `heights_weights` data frame with three columns (height_cm, weight_kg, age_years), render a clean scatter using bare column names in aes(). Visible plot is the payoff.

**Interpretation:** Bare names map to columns. ggplot2 looked up `height_cm` and `weight_kg` inside `heights_weights` and drew one point per row.

**Code block 2 (deliberate error, caught):** Re-use the same data frame, reference `heights` (wrong) in aes(), wrap `print()` in `tryCatch()` to capture and display the literal error message as a string. Shows readers the exact error text they'll see.

**Callout:** `[KEY INSIGHT]` — aes() captures expressions instead of evaluating them, and resolves names against the data frame first.

### Core H2-2: Is the missing name supposed to be a column or an R variable?

**Opening prose (~70 words):**
Before you reach for a fix, answer one question: should this name refer to a column inside the data frame, or to a value sitting in your workspace? The answer decides where the name goes. Columns belong inside `aes()` as bare names; numbers, sizes, colors, and thresholds belong outside `aes()` as plain arguments to `geom_*`.

### Core H2-3: How do you use a column name stored in a variable?

**Opening prose (~70 words):**
If you write a function that receives a column name as a string, the natural attempt `aes(x = col_name)` fails — ggplot2 looks for a column literally named "col_name". The modern fix is `.data[[col_name]]`, a tidy-eval pronoun that tells aes() to treat `col_name` as a string lookup against the current data frame. This single pattern replaces every older hack.

**Code block 5:** String variable `col_name <- "height_cm"`. Show broken attempt as a *commented line* (we already demonstrated tryCatch in H2-1, no need to repeat). Show the working `.data[[col_name]]` version.

**Callout:** `[WARNING]` — `aes_string()` is soft-deprecated. New code should use `.data[[var]]` instead.

### Core H2-4: What causes a column to disappear inside a pipeline?

**Opening prose (~70 words):**
When `ggplot()` sits at the end of a `dplyr` pipeline, a transformation upstream can silently drop or rename the column you meant to plot. The error surfaces at the ggplot step, but the real cause is a few pipes earlier. This is one of the most confusing sources of "object not found" because the column existed a moment ago.

**Code block 7:** Pipeline that does `select(name, sales)` then tries to color by `region` in ggplot. Catch with `tryCatch(print(...))`. Then fix by reordering or dropping the over-eager `select()`.

**Callout:** `[TIP]` — insert `glimpse()` or `head(1)` between pipe steps while debugging to see which columns survive each step.

**Inline exercise 4:** Fix a broken pipeline that `select()`s only two columns and then tries to map a third. Scaffold + reveal.

### Core H2-5: How do you handle column names with spaces or dots?

**Opening prose (~60 words):**
R lets data frames have any name — with spaces, punctuation, even leading digits — but `aes()` parses bare tokens, so spaces split the name into two meaningless pieces. The fix is backticks around the full name, or renaming columns to snake_case before plotting.

**Code block 8:** Data frame with `First Name` and `Test Score` columns (using `check.names = FALSE`). Show the backtick version inside aes(). Show the cleaner `janitor::clean_names()` alternative (fallback to `names()<-` if janitor unavailable in WebR — use base R).

**Callout:** `[TIP]` — fix names once at import time with a `names(df) <- tolower(gsub(" ", "_", names(df)))` one-liner, then drop the backticks forever.

**Inline exercise 5:** Given a df with an `Annual Income` column, write a working aes() call. Scaffold + reveal.

#### H2: Exercise 1 — Can You Write a Pure Function That Scales a Vector?

- **Concept:** Pure functions (no side effects, same input → same output)
- **Difficulty:** Easy
- **Task:** Write `scale_between(x, low, high)` that scales a numeric vector to a [low, high] range. Must be pure.
- **Starter code:** function signature + test call with expected output
- **Solution:** uses `(x - min(x)) / (max(x) - min(x)) * (high - low) + low`
- **Callout:** None

#### H2: Exercise 2 — Can You Spot and Fix the Impure Function?

- **Concept:** Pure vs impure, global state, side effects
- **Difficulty:** Easy-Medium
- **Task:** Given an impure function that uses `<<-`, rewrite it as pure.
- **Starter code:** impure version + test expectations
- **Solution:** Replace global mutation with return-based state
- **Callout:** [KEY INSIGHT] on why pure functions are easier to test

#### H2: Exercise 3 — Can You Store Functions in a List and Dispatch by Name?

- **Concept:** First-class functions, function lists
- **Difficulty:** Easy
- **Task:** Create a named list of summary functions (mean, median, sd, IQR) and write `summarise_with(x, stat_name)` that dispatches.
- **Starter code:** function skeleton + test calls
- **Solution:** Named list lookup + call
- **Callout:** None

#### H2: Exercise 4 — Can You Build a Function Factory for Power Functions?

- **Concept:** Function factories / closures
- **Difficulty:** Medium
- **Task:** Write `make_power(n)` that returns a function raising its argument to the nth power. Use it to create `square` and `cube`.
- **Starter code:** factory skeleton + test expectations
- **Solution:** Closure capturing `n`
- **Callout:** [TIP] on closures capturing the enclosing environment

#### H2: Exercise 5 — Can You Replace a For Loop With Map?

- **Concept:** Higher-order functions — map (sapply/Map)
- **Difficulty:** Medium
- **Task:** Given a for loop that normalises each column of a data frame, rewrite using `sapply`.
- **Starter code:** the for-loop version + expected output
- **Solution:** `sapply(df, \(col) (col - mean(col)) / sd(col))`
- **Callout:** None

#### H2: Exercise 6 — Can You Chain Filter and Reduce to Solve a Data Problem?

- **Concept:** Higher-order functions — Filter + Reduce
- **Difficulty:** Medium
- **Task:** From a list of mixed values (numbers + strings), keep only positive numbers and compute their running product using `Filter` and `Reduce`.
- **Starter code:** mixed list + expected output
- **Solution:** `Filter(\(x) is.numeric(x) && x > 0, mixed) |> Reduce(\`*\`, x = _)`
- **Callout:** [WARNING] on Reduce needing at least one element

#### H2: Exercise 7 — Can You Write Your Own Map From Scratch?

- **Concept:** Implementing higher-order functions
- **Difficulty:** Hard
- **Task:** Implement `my_map(x, f)` that applies `f` to each element of vector `x` and returns a list, without using any apply/map function.
- **Starter code:** function skeleton + test cases
- **Solution:** Pre-allocate list, loop, return
- **Callout:** [KEY INSIGHT] on understanding HOFs by building them

#### H2: Exercise 8 — Can You Prove That R's Copy-on-Modify Keeps Your Data Safe?

- **Concept:** Immutability, copy-on-modify
- **Difficulty:** Medium
- **Task:** Write a function that modifies its input in multiple ways. Prove the original is untouched by running a before/after check.
- **Starter code:** a data frame + function skeleton + verification pattern
- **Solution:** Modify inside function, show `identical(original, ...)` is TRUE
- **Callout:** None

#### H2: Exercise 9 — Can You Compose Three Functions Into a Single Pipeline?

- **Concept:** Function composition, pipes
- **Difficulty:** Hard
- **Task:** Given three small helper functions, compose them into a single pipeline that cleans a character vector (trim → lowercase → remove punctuation), using the native pipe `|>`.
- **Starter code:** three helpers + messy input + expected output
- **Solution:** `x |> trimws() |> tolower() |> gsub("[[:punct:]]", "", x = _)`
- **Callout:** [TIP] on using the `_` placeholder with `|>`

#### H2: Exercise 10 — Can You Build a Memoised Fibonacci Function?

- **Concept:** Memoisation, closures, recursion
- **Difficulty:** Hard
- **Task:** Write a Fibonacci function that caches results using a closure (environment as cache), then show it's faster on repeated calls.
- **Starter code:** naive recursive fib + skeleton for memoised version
- **Solution:** Environment-based cache inside closure
- **Callout:** [KEY INSIGHT] on memoisation as a functional pattern

### Lead sentence (for featured snippet)
`lobstr is the diagnostic toolkit for R's memory system: obj_size() measures true object size accounting for shared data, ref() shows which objects secretly share RAM, and mem_used() reports how much memory your session is really holding.`

### First H2 opening prose (≤80 words)
"Why does `object.size()` lie about R memory?"
Opening: "Run `object.size()` on a list with repeated data and it happily tells you the list uses 10× more memory than it really does. R silently shares values behind the scenes, and the built-in counter never notices. `lobstr::obj_size()` notices — and the gap is bigger than you'd guess. Let's put them head to head on a list you'd actually build." (~70 words)

### Core H2 sections

**H2-1: Why does `object.size()` lie about R memory?** (entry-point H2)
- Theory: base R's `object.size()` was designed before reference-sharing mattered much; it sums components naively.
- Code block 1 (PAYOFF): `library(lobstr)`, build `big_vec <- runif(1e4)`, `shared_list <- rep(list(big_vec), 100)`, compare `object.size(shared_list)` vs `obj_size(shared_list)`. Output shows ~8 MB vs ~80 kB.
- Interpretation: lobstr detects that all 100 list slots point at the same vector. Real RAM cost is one copy plus 100 pointers.
- Inline exercise: make a list of 50 duplicated vectors and measure both ways.
- Callout: [KEY INSIGHT] about why sharing matters.

**H2-2: How does `obj_size()` measure true object size?**
- Theory: `obj_size()` walks the object, includes environments, credits shared parts once, understands ALTREP.
- Code block 2: `obj_size(mtcars)`, `obj_size(mtcars, iris)` — multi-arg counts combined size minus overlap.
- Code block 3: ALTREP demo — `obj_size(1:1e6)` returns ~680 B because R stores a range, not a vector.
- Interpretation of each.
- Inline exercise: pass two copies of a data frame to `obj_size()` together and predict the combined size.
- Callout: [NOTE] about ALTREP.

**H2-3: How can you see shared references with `ref()`?**
- Theory: `ref()` prints a tree with memory addresses and unique IDs. Same ID = same underlying object.
- Code block 4: `y <- shared_list` then `ref(shared_list, y)`, observe shared IDs. Then `y[[1]] <- rnorm(10)`, call `ref(shared_list, y)` again — the changed slot gets a new ID, the rest still share.
- Interpretation: this is copy-on-modify happening in real time; only the touched branch copies.
- Inline exercise: make `a <- 1:3; b <- a; b[1] <- 0` and run `ref(a, b)` to spot the split.
- Callout: [TIP] about using `ref(..., character = TRUE)` to see the string pool.

**H2-4: How do you check total R memory with `mem_used()`?**
- Theory: `mem_used()` is a friendly wrapper around `gc()` that returns the bytes R currently holds.
- Code block 5: `mem_used()` baseline, allocate `huge <- rnorm(5e6)`, call `mem_used()` again and diff. Then `rm(huge); gc(verbose = FALSE); mem_used()`.
- Interpretation: show the delta and why the post-rm number is close to but not identical to baseline.
- Inline exercise: capture two `mem_used()` snapshots and compute the delta after creating a vector of a given size.
- Callout: [WARNING] that `mem_used()` won't match OS reporting due to lazy GC.

**H2-5: How does `obj_addr()` pinpoint where a variable lives?**
- Theory: `obj_addr()` returns the hexadecimal memory address of the object a name points to. Identical addresses prove identity (not just equality).
- Code block 6: `a <- c(10, 20, 30); b <- a; obj_addr(a); obj_addr(b)` — equal. Then `b[1] <- 99; obj_addr(a); obj_addr(b)` — different.
- Interpretation: modify-in-place becomes copy-on-modify the instant a second binding exists.
- Inline exercise: take a vector, assign to two names, modify one, confirm the original address with `obj_addr()`.
- Callout: [KEY INSIGHT] that `obj_addr()` is the ground truth for "same object or not".

**H2-6: How do you diagnose memory-hungry code?**
- Theory: a realistic workflow — baseline `mem_used()`, call the suspect function, check `obj_size()` on the returned object, use `ref()` if surprising.
- Code block 7: define `bloated_stats()` that computes per-group means but returns the entire input alongside. Profile it. Show the smaller rewrite using `dplyr::summarise()`.
- Interpretation: compare `obj_size()` before/after and `mem_used()` delta.
- Inline exercise: swap in a different group variable and check whether the bloat is proportional.
- Callout: [TIP] "profile first, guess last".

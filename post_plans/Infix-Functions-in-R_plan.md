### Lead Paragraph

"An infix function in R is a function you call *between* its two arguments — like `x + y` or `a %in% b` — instead of the usual `func(x, y)` prefix style. You can define your own infix operators using the `%name%` syntax, turning any two-argument function into a readable operator."

### H2 1: What Are Infix Functions and Why Does R Use Them?

**Opening prose (≤80 words):** Every operator you type in R — `+`, `-`, `*`, `<`, even `[` — is secretly a function. R just lets you write it *between* the arguments instead of wrapping them in parentheses. This "infix" style is why `3 + 5` feels natural while `sum(3, 5)` feels mechanical. Understanding this reveals a powerful idea: if built-in operators are just functions, you can make your own.

**Theory/intuition:** Prefix vs infix form. Every R operator can be called in prefix form with backticks. This is the foundation.

**Code blocks:**
1. Show `3 + 5` and its prefix equivalent `` `+`(3, 5) ``. Also show `10 %in% c(1, 10, 100)` and its prefix form. Demonstrate that operators ARE functions.

**Callout:** KEY INSIGHT — Every R operator is a function. The `+` in `3 + 5` is syntactic sugar for `` `+`(3, 5) ``.

**Inline exercise:** Convert `x * y - z` into fully prefix form using backtick notation. Verify both produce the same result.

### H2 2: How Do You Create a Custom %op% Infix Operator?

**Theory/intuition:** The `%name%` naming convention. Define a two-argument function, wrap the name in `%`, assign with backticks. Walk through step by step.

**Code blocks:**
1. Create a `%plus%` operator that adds two numbers. Show usage both as infix and prefix.
2. Create a `%divisible%` operator that checks divisibility. Show TRUE/FALSE results.
3. Create a `%paste%` string concatenation operator. Show practical string building.

**Callout:** TIP — Keep operator names short and descriptive. `%ni%` (not in) beats `%not_in_vector%`.

**Inline exercise:** Create a `%between%` operator that checks if `x` is between the min and max of a length-2 vector `y`. Test with `15 %between% c(10, 20)`.

### H2 3: What Naming Rules Apply to Custom Infix Operators?

**Theory/intuition:** R is surprisingly permissive with infix names. Any characters except `%` are allowed. Special characters need escaping in the definition but NOT when calling. Show examples of unusual names.

**Code blocks:**
1. Operators with spaces, punctuation in names: `` `% %` ``, `` `%±%` ``. Show defining and calling each.
2. Show the one hard rule: no `%` inside the name. Demonstrate the error.

**Callout:** WARNING — Avoid special characters in operator names even though R allows them. Stick to alphanumeric + underscores for readability: `%ni%`, `%like%`, `%has%`.

**Inline exercise:** Create an operator called `%greet%` that pastes the left argument, " says hello to ", and the right argument. Test with `"Alice" %greet% "Bob"`.

### H2 4: How Does Operator Precedence Work With Custom Infix Operators?

**Theory/intuition:** All custom `%op%` operators share the same precedence level (between `+` and comparison operators). They associate left to right. This can produce surprises.

**Code blocks:**
1. Chain three custom infix calls to show left-to-right evaluation. Use Hadley's parentheses trick to make evaluation order visible.
2. Show a precedence surprise: `1 + 2 %custom% 3` vs `(1 + 2) %custom% 3`. Demonstrate how `%custom%` binds tighter than `+`.

**Callout:** WARNING — Custom `%op%` operators bind tighter than `+` and `-` but looser than `*` and `/`. When in doubt, add parentheses.

**Inline exercise:** Predict and verify the result of `2 + 3 %plus% 4` given `%plus%` adds its arguments. Does it give 9 or 7?

### H2 5: What Are Some Practical Custom Infix Operators You Can Build?

**Theory/intuition:** Move from toy examples to genuinely useful operators. Show a toolkit of operators people actually want.

**Code blocks:**
1. `%ni%` — "not in" (negation of `%in%`). The most-requested missing operator in base R. Show filtering with it.
2. `%||%` / `%??%` — null/default coalescing. Returns left side if not NULL, otherwise right side. Like Python's `or` or JavaScript's `??`.
3. `%like%` — case-insensitive pattern matching with `grepl()`. Filter strings easily.
4. `%+%` — string concatenation (paste0). Build strings without nested function calls.

**Callout:** KEY INSIGHT — The best custom operators encode a *pattern you repeat often*. If you write `!x %in% y` ten times a day, `%ni%` saves keystrokes and prevents the precedence bug where `!` binds to `x` instead of the whole expression.

**Inline exercise:** Create a `%clamp%` operator that clamps `x` between `min(y)` and `max(y)` where `y` is a length-2 vector. Test with `150 %clamp% c(0, 100)` expecting 100.

### H2 6: When Should You Write a Custom Infix Operator (and When Should You Not)?

**Theory/intuition:** Guidelines for good judgment. Custom operators are powerful but can hurt readability if overused. Cover: when they help (frequent patterns, team conventions, package APIs), when they hurt (obscure names, one-off use, complex logic).

**Code blocks:**
1. Side-by-side: a pipeline with custom operators vs. the same logic with regular functions. Show where operators improve readability and where they obscure it.

**Callout:** TIP — Write a custom operator when it makes the *calling* code clearer, not the *definition* code. If a colleague can't guess what `x %op% y` does from the name alone, use a regular function instead.

**Inline exercise:** Refactor a nested expression `paste0(toupper(substr(x, 1, 1)), substr(x, 2, nchar(x)))` into a single `%titlecase%` operator call. (Capitalize first letter.)

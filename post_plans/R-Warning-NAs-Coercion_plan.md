## C. Outline

**Lead (1-2 sentences):** The warning "NAs introduced by coercion" fires whenever `as.numeric()` meets a value it can't parse — `"N/A"`, `"$1,200"`, `"3,14"`, a stray space. R silently replaces each unparseable value with `NA` and keeps running, so bad data sneaks into your analysis unnoticed.

**First H2 opening prose (~65 words, before payoff block):**
"The warning is R's way of saying *some, but not all, of your values parsed*. It keeps the clean ones and swaps the rest with `NA`. The fast diagnostic: catch the coerced vector, then ask `which(is.na(...))` — that prints the exact positions that failed, so you can print the originals and see what broke."

### Core H2 sections (4)

**Core 1 — Why does `as.numeric()` return NAs with a warning?**
- Theory: `as.numeric()` calls R's internal parse. Non-parseable → NA, one warning emitted per call (not per bad value).
- Block 1 (PAYOFF): `raw <- c("23.5", "18", "N/A", "31.2", "error", "27.8")` → `parsed <- suppressWarnings(as.numeric(raw))` → `which(is.na(parsed))` → `raw[which(is.na(parsed))]` shows "N/A" and "error".
- Callout: [KEY INSIGHT] on `which(is.na())` being the diagnostic.
- Inline exercise: given a vector, print only the culprits (not their positions).

**Core 2 — How do you clean text placeholders before converting?**
- Theory: replace known placeholder strings with `NA` *before* `as.numeric()` so the warning is intentional, not accidental.
- Block 2: `readings <- c("23.5", "18", "N/A", "31.2", "missing", "27.8")` → `readings[readings %in% c("N/A","missing","","NA","-","TBD")] <- NA_character_` → `as.numeric(readings)`.
- Callout: [TIP] standardise a placeholder list at the top of your script.
- Inline exercise: clean a vector with "unknown" and "n/a".

**Core 3 — How do you strip currency, commas, percent signs, and whitespace?**
- Theory: `gsub()` to remove formatting characters; `trimws()` for whitespace.
- Block 3: `prices <- c(" $1,200 ", "$850.00", "2,100.50", "98%")` → `trimws()` → `gsub("[$,%]", "", x)` → `as.numeric()`.
- Callout: [NOTE] `readr::parse_number()` as a one-liner alternative.
- Inline exercise: clean a vector with "£" and "k" suffixes.

**Core 4 — Why do factors and European decimals still break `as.numeric()`?**
- Theory: (a) `as.numeric(factor)` returns *level indices*, not the value; (b) locales using `,` as decimal separator.
- Block 4a: `grades <- factor(c("90", "85", "72"))` → `as.numeric(grades)` (gives 3,2,1) vs `as.numeric(as.character(grades))` (gives 90,85,72). Then non-numeric labels `factor(c("A","B"))` → NAs with warning.
- Block 4b: `eu <- c("3,14", "2,72")` → `gsub(",", ".", eu)` → `as.numeric()`. Mention `read.csv2()` for European CSVs.
- Callout: [WARNING] the factor trap — the most confusing silent bug.
- Inline exercise: convert `factor(c("100","200","300"))` correctly.

## C. Full Section Outline

### Lead paragraph
Tail call optimization (TCO) lets a recursive function reuse its current stack frame instead of adding a new one for each call — so your recursion runs in constant memory and never hits R's stack limit. R 4.4+ supports this natively with `Tailcall()`, and older versions can achieve the same effect with trampolines or accumulator rewrites.

### First H2 opening plan (≤80 words)
"Every recursive call in R adds a frame to the call stack. Call yourself enough times and R crashes with 'C stack usage is too close to the limit.' Let's see this happen, then fix it."

### Core H2 Sections

#### H2-1: Why does recursion hit a stack limit in R?
- **Theory/intuition:** R maintains a call stack. Each recursive call pushes a frame. Stack is finite (~1000-10000 frames depending on system). Demonstrate the crash.

- **Callout:** [KEY INSIGHT] The stack limit exists to protect your system from runaway recursion eating all memory.

#### H2-2: What makes a function tail-recursive?
- **Theory/intuition:** A function is tail-recursive when the recursive call is the very last operation — nothing happens after it returns. Contrast: `n * factorial(n-1)` is NOT tail-recursive (multiplication happens after). `factorial(n-1, acc*n)` IS tail-recursive (call is last).
- **Code blocks:**
  1. Non-tail-recursive factorial — show why the multiplication must wait on the stack.
  2. Tail-recursive factorial with accumulator — show how the result travels forward.
- **Callout:** [TIP] The trick: move the "pending work" into a parameter (the accumulator) so nothing remains after the recursive call returns.
- **Inline exercise:** Rewrite a non-tail-recursive `power(base, exp)` into tail-recursive form with an accumulator.

#### H2-3: How does Tailcall() work in base R?
- **Theory/intuition:** R 4.4 introduced `Tailcall()` in base R. It replaces the current stack frame instead of pushing a new one. The recursive call must be the last expression (tail position). Experimental feature but works well.
- **Code blocks:**
  1. Factorial using `Tailcall()` — handles n=100000 without stack overflow.
  2. Countdown using `Tailcall()` — compare to the crashing version from H2-1.
- **Callout:** [WARNING] `Tailcall()` is experimental in R 4.4. Stack traces from `traceback()` won't show replaced frames — debugging gets harder.
- **Callout:** [NOTE] `Tailcall()` requires R >= 4.4.0. Check your version with `R.version.string`. The WebR runtime used on this page may not yet support it — run these examples locally if needed.
- **Inline exercise:** Convert a recursive `fibonacci_sum(n)` that sums the first n Fibonacci numbers into a `Tailcall()` version.

#### H2-4: What is the trampoline pattern and when should you use it?
- **Theory/intuition:** A trampoline wraps recursion in a loop. Instead of calling itself, the function returns a "thunk" (a deferred call). The loop unwraps thunks until a final value appears. Works on any R version, no special functions needed.
- **Code blocks:**
  1. Minimal trampoline + recur implementation (Jim Hester's pattern — ~8 lines).
  2. Factorial with the trampoline — handles deep recursion.
  3. Mutual recursion (even/odd) with trampolines — show the function-returning variant.
- **Callout:** [KEY INSIGHT] A trampoline converts recursion into iteration without you having to rewrite the algorithm as a loop. The recursive structure stays readable.
- **Inline exercise:** Use the trampoline to write a `collatz(n)` function that counts steps to reach 1.

#### H2-5: How do you choose between Tailcall(), trampolines, and loops?
- **Theory/intuition:** Decision framework. Tailcall() is simplest but needs R 4.4+. Trampolines work everywhere but add overhead. Plain loops are fastest but lose recursive clarity. Show a comparison table.

- **Callout:** [TIP] For production code on R < 4.4, use the trampoline pattern. For R 4.4+, prefer `Tailcall()` for simplicity. For hot loops, just write a loop.

## C. Full Section Outline

### Lead sentence (featured snippet)

`Error in x[i] <- value : replacement has length zero` means the right side of your assignment evaluated to *nothing* — a `NULL`, an empty vector, or a missing index — so R has no value to place into `x[i]`. It almost always traces back to a filter, lookup, or subscript that silently returned zero rows.

### First H2 opening plan (~80 words)

**H2:** `## What does "replacement has length zero" actually mean?`

**Opening prose:** The error fires when R tries to execute `x[i] <- value` and finds that `value` has length zero. The assignment slot still expects one concrete element, so R refuses and throws. The tricky part is that the right-hand side rarely *looks* empty — it came from a filter, a `grep()`, a `which()`, or a lookup whose key wasn't in the table. Reproducing the failure in a familiar `for` loop makes the mechanism obvious.

**Payoff code block (Block 1):** A `for`-loop that tries to enrich a vector of names with ages from a lookup table. One of the names (Bob) isn't in the table. The lookup returns `numeric(0)`, which crashes the assignment inside the loop. Output shows the exact error message.

**KEY INSIGHT callout** after interpretation: the error is always about *mismatched cardinality on an assignment* — the slot wants 1, the RHS has 0.

**Inline exercise (Try it 1):** Reader rewrites the loop to skip empty lookups with a `length() > 0` guard.

### Core H2 sections

**H2 2:** `## Which RHS patterns silently produce a zero-length result?`

Catalog the four workhorses that return `integer(0)` / `character(0)` / `numeric(0)`:

1. **`grep()` with no match** → `integer(0)`
2. **`which()` on an always-false logical** → `integer(0)`
3. **Positional filter `v[v > threshold]` with nothing above threshold** → zero-length vector
4. **Data frame row filter `df[df$col == key, "val"]` with no match** → zero-length vector

- Code block (Block 2): runs all four side-by-side and inspects `length()` of each.
- TIP callout: "Every zero-length value you assign into a scalar slot throws the same error — the diagnosis is always `length(rhs)`."
- Inline exercise (Try it 2): given a `grep()` that may or may not match, reader writes a guarded assignment.

**H2 3:** `## How do you diagnose a zero-length assignment before R does?`

Teach three active diagnostics readers can drop into any pipeline:

1. `length()` at the exact spot — dump it with `print(length(rhs))`
2. `stopifnot(length(rhs) == 1L)` — fail loudly at the source, not 30 lines later
3. `any(is.na(idx))` — detect NA indexes that propagate into hidden zero-length slices
4. `nrow(filtered) > 0` check before `filtered$col[[1]]`

- Code block (Block 3): a small function `safe_lookup()` that wraps a lookup with `stopifnot()` so the error names the missing key.
- WARNING callout: debuggers can't always reach *inside* `sapply()`/`vapply()` — isolate the failing iteration first.
- Inline exercise (Try it 3): add a `stopifnot()` guard to a provided function so it fails with a readable message.

**H2 4:** `## Which defensive patterns prevent the error in production code?`

Four reusable patterns:

1. **`%||%` null-coalesce helper** — returns a default when the RHS is `NULL` or length-0
2. **`match()` with a default** — `match(key, table, nomatch = NA_integer_)` never returns 0-length
3. **Vectorised lookup** — skip the `for` loop entirely; `ages_table$age[match(people, ages_table$name)]` returns NA for misses, which is assignable
4. **`dplyr::coalesce()`** — for pipelines that already use dplyr

- Code block (Block 4a): the `%||%` pattern in base R.
- Code block (Block 4b): vectorised `match()` lookup, showing NA in the output rather than a crash.
- NOTE callout: `rlang::%||%` ships in tidyverse — no need to redefine if rlang is loaded.
- Inline exercise (Try it 4): reader writes a `safe_first()` helper that returns NA on empty input.

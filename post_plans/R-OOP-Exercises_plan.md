## Lead (featured snippet)

These 8 practice problems build real fluency in R's three major OOP systems — **S3** (informal), **S4** (formal, validated), and **R6** (mutable reference) — plus operator overloading and method dispatch. Every exercise ships with starter code and a worked solution you can run in the browser.

## Core sections (each H2 = one exercise, phrased as a question)

### Exercise 1: Can You Build an S3 Temperature Class?
- Concept: S3 constructor pattern, `class()`, `structure()`, first `print.Temperature` method
- Code blocks: 1 starter + 1 solution inside `<details>`
- Callout: [TIP] — "Prefix S3 methods with the class name: `print.Temperature`, not `Temperature.print`."

### Exercise 2: Can You Write a Generic That Dispatches to Three Methods?
- Concept: `UseMethod()`, writing class-specific methods for numeric/character/factor, default method
- Code blocks: 1 starter + 1 solution
- Callout: [KEY INSIGHT] — "S3 dispatch is just string matching — R looks for `describe.<class>` and falls back to `describe.default`."

### Exercise 3: Can You Create an S4 Account Class With Validation?
- Concept: `setClass()`, `representation()`, `setValidity()`, `setGeneric()`, `setMethod()`, the `new()` constructor
- Code blocks: 1 starter + 1 solution
- Callout: [WARNING] — "Validity runs on `new()` *and* every slot write via `@`. A failed validity check aborts the write."

### Exercise 4: Can You Use S4 Multiple Dispatch for Geometric Intersections?
- Concept: `setGeneric()` with `signature=`, methods dispatching on two arguments (`Circle`×`Circle`, `Circle`×`Rectangle`, `Rectangle`×`Rectangle`)
- Code blocks: 1 starter + 1 solution
- Callout: [TIP] — "When you write `setMethod("intersects", signature("Circle", "Rectangle"), ...)`, order matters. `intersects(r, c)` won't find the method unless you add the reversed signature too."

### Exercise 5: Can You Build a Counter Class With R6?
- Concept: `R6Class()`, `public`, `private`, `self$`, `private$`, `initialize`, methods that mutate state
- Code blocks: 1 starter + 1 solution
- Callout: [KEY INSIGHT] — "R6 objects are *references*. Calling `$increment()` changes the original — there's no copy-on-modify."

### Exercise 6: Can You Extend Counter Into a BoundedCounter?
- Concept: R6 inheritance via `inherit =`, `super$`, overriding `initialize`, calling parent methods
- Code blocks: 1 starter + 1 solution
- Callout: [NOTE] — "`super$increment()` calls the parent's method even after you've overridden it. That lets you add guards without re-implementing logic."

### Exercise 7: Can You Overload + and - for an S3 Money Class?
- Concept: `Ops` group generic, `Ops.Money`, operator dispatch via `.Generic`, custom `print.Money`
- Code blocks: 1 starter + 1 solution
- Callout: [TIP] — "Defining `Ops.<class>` one time gets you `+`, `-`, `*`, `/`, `==`, `<`, and 14 other operators for free. Inspect `.Generic` to decide which one you're handling."

### Exercise 8: Which OOP System Should You Pick for Each Scenario?
- Concept: Decision-making across S3/S4/R6. Three scenarios: (a) ephemeral summary object returned from a function, (b) pharma data model where every row must pass strict validation, (c) a game loop where a player's HP mutates every tick
- Code blocks: 1 starter (pseudo-code stub) + 1 solution (minimal working sketch for each)
- Callout: [KEY INSIGHT] — "Pick S3 for simplicity, S4 for validation, R6 for mutation. Those three words cover 95% of real decisions."

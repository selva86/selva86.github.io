## C. Full Section Outline

### Lead Paragraph

**Lead sentence (featured snippet):** S3 method dispatch is R's mechanism for deciding which function implementation to run when you call a generic like `print()` or `summary()` — R inspects the object's class attribute, searches for a matching method name, and calls the first one it finds.

### First H2 Opening Prose (≤80 words)

"Every time you type `print(x)`, R doesn't just run one fixed function. It checks what *kind* of object `x` is, builds a method name from the generic and the class, and calls that specific function. This is S3 method dispatch — and it powers almost every interaction you have with R. Let's see it in action."

### Core Section 1: What happens when you call a generic function like print()?

**Theory/intuition:** Generic functions are thin wrappers around UseMethod(). When you call `print(x)`, R never actually runs the body of `print()` beyond the UseMethod() call. Instead, it looks at `class(x)`, constructs a method name like `print.factor`, and calls that function.

2. Show that `print` body is just `UseMethod("print")`. Show `body(print)`.

**Callouts:** KEY INSIGHT — Every generic is just a one-line function that calls UseMethod().

### Core Section 2: How does UseMethod() search for the right method?

**Theory/intuition:** The three-place search algorithm. When UseMethod("generic") runs, R looks in: (1) the method table (.__S3MethodsTable__. in the generic's environment), (2) the calling environment chain up to the global environment, (3) the base environment. It constructs names as `generic.class` for each class in the class vector, then tries `generic.default`.

**Code blocks:**

**Callouts:** WARNING — UseMethod() never returns to the generic's body. Code after UseMethod() is unreachable.

### Core Section 3: What role does the class vector play in dispatch?

**Theory/intuition:** An object's class isn't always a single string — it can be a character vector like `c("glm", "lm")`. R walks this vector left to right, trying `generic.class1`, then `generic.class2`, and so on. The order of classes in the vector determines which method wins.

### Core Section 4: How does NextMethod() delegate to parent classes?

**Theory/intuition:** NextMethod() lets a child method do its work and then pass control to the next method in the class chain. It doesn't restart dispatch — it picks up from the *next* class in the vector. R tracks position via the internal `.Class` variable.

**Code blocks:**

**Callouts:** WARNING — Don't modify the object before calling NextMethod(). Changes to the dispatched argument are ignored; R uses the original.

**Inline exercise:** Add a `describe.puppy()` method that prints the puppy's name, then calls NextMethod() to also print the dog breed. Verify both lines appear.

### Core Section 5: How do internal generics and group generics dispatch differently?

**Theory/intuition:** Not all dispatch goes through UseMethod(). Internal generics (like `[`, `+`, `c`) are implemented in C and dispatch at the C level. Group generics (Ops, Math, Summary, Complex) let you handle entire families of operations with one method.

**Code blocks:**

**Callouts:** KEY INSIGHT — Group generics let you write one method to handle dozens of operators. The `.Generic` variable tells you which operator was actually called.

**Inline exercise:** Create a `Summary.currency` method that handles `sum()` and `max()`. Test it with a vector of currency values.

### Core Section 6: How do you inspect and debug S3 dispatch?

**Theory/intuition:** When dispatch goes wrong, you need tools to see what R is doing. `methods()` lists available methods, `getAnywhere()` finds hidden ones, and manual tracing lets you see the lookup sequence.

**Code blocks:**

**Callouts:** TIP — Use `methods(class = "yourclass")` after defining a new class to verify all your methods are registered.

**Inline exercise:** Use `methods()` to find all methods defined for the `Date` class. Count how many there are.

### Summary

|---|---|
| UseMethod("generic") | Starts method dispatch |

## Lead paragraph

The message "argument is not a matrix" (and its modern cousin `'X' must have at least 2 dimensions`) means you handed `apply()` something it can't treat as a rectangular, single-type grid — usually a data frame with mixed columns, a list, or a plain vector. The fix is to pick the right tool: convert the structure honestly, or switch to `lapply()`, `sapply()`, `vapply()`, or `dplyr::across()`.

## First H2 opening plan

H2: **Why does apply() throw "argument is not a matrix"?**

Opening prose (≤80 words): `apply()` is a matrix function wearing a friendly face. Internally it calls `as.matrix()` on your input and demands a rectangular, single-type grid. A vector has no rows and columns, a list has no shape at all, and a mixed data frame forces every number to become a character. Any of these trips the error. The fastest way to see the fix is to watch it happen.

Payoff code block (Block 1): reproduce the error on a data frame and show a one-line `as.matrix()` fix that returns actual row means.

### H2-2: How do you convert a data frame correctly?
- Intuition: selecting numeric columns BEFORE matrix coercion preserves numbers
- Block 2: iris with Species (factor). Naïve `as.matrix(iris)` → all chr. `as.matrix(iris[, 1:4])` → numeric. Show `typeof()` before/after.
- Callout: [WARNING] mixed-type apply silently returns character output — no error, wrong result

### H2-3: When should you use lapply, sapply, or vapply instead?
- Intuition: lists and vectors don't have dimensions — use the list-aware family
- Block 3: list of numeric vectors → `apply()` errors → `sapply(l, mean)` works; add `vapply()` with type declaration

### H2-4: How do you do this the tidyverse way with dplyr::across()?
- Intuition: across() is the modern replacement for applying a function to many columns
- Block 4: starwars data frame → `summarise(across(where(is.numeric), mean, na.rm = TRUE))`
- Callout: [NOTE] dplyr 1.1+ supersedes the older mutate_if()/summarise_at() variants

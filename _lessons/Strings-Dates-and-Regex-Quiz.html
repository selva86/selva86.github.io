Question 1 of 8

What str_detect returns

You run str_detect(c("apple", "pear", "grape"), "ap"). What comes back?

Right. str_detect() reports whether each string contains the pattern, so you can use it to filter.
That is str_locate(); str_detect() gives TRUE or FALSE.
Question 2 of 8

A digit in a regex

In an R string, how do you write the regular expression that matches a single digit?

Correct. R sees \\ as one backslash, so the regex engine receives \d, the digit class.
That matches the literal letters d, i, g, i, t; the digit class is \\d or [0-9].
Question 3 of 8

First match or all of them

str_replace() and str_replace_all() differ how?

Right. Reach for the _all variant when a pattern can appear more than once.
It replaces all matches, not just the last.
Question 4 of 8

Parsing a date

You have the text "2026-03-08" and want a real date you can do arithmetic on. With lubridate, which call parses it?

Correct. lubridate's parser is named for the order of the parts, so ymd fits this text.
That keeps it as text; you want a Date object.
Question 5 of 8

What a factor's levels are

You make factor(c("low", "high", "low")). What are its levels?

Right. A factor stores the full set of permitted categories, which is what lets you order and count them cleanly.
Levels are the defining feature of a factor.
Question 6 of 8

Anchoring a pattern

In a regular expression, what does the ^ at the start of a pattern mean?

Right. ^abc matches only when the string begins with abc; pair it with $ to anchor the end.
Repetition is * or +; ^ anchors position.

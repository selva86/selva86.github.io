Question 1 of 6

The accuracy trap

A fraud model where 1% of cases are fraud reports 99% accuracy. The likely explanation is:

Correct: with 1% positives, always guessing the majority scores 99% while catching zero fraud.
The imbalance is what makes accuracy misleading here.
Question 2 of 6

Resampling done right

When you upsample or apply SMOTE to fix class imbalance, you must:

Correct: rebalancing the evaluation data leaks and inflates the score; test on the real distribution.
Both are valid; the rule is where you apply them, not which.
Question 3 of 6

Setting the threshold

The default 0.5 classification cutoff is often wrong for imbalanced or costly problems because:

Correct: when a missed fraud costs far more than a false alarm, you lower the threshold.
There is no fixed rule; the cost structure decides.
Question 4 of 6

ROC versus PR

Under heavy class imbalance, the precision-recall curve is often more informative than ROC because:

Correct: PR focuses on the positive class you actually care about.
They can tell very different stories under imbalance.
Question 5 of 6

What calibration means

A classifier is well-calibrated when:

Correct: calibration means the predicted probability matches the observed frequency.
AUC measures ranking, not whether a 0.7 means 70%.
Question 6 of 6

What a single AUC hides

Reporting only AUC can mislead because AUC:

Correct: two models with equal AUC can behave very differently at the threshold you deploy.
AUC is defined regardless of balance; the issue is what it omits.
Run it: the accuracy paradox

High accuracy, zero recall

Build an imbalanced outcome, predict the majority class for everyone, and see accuracy stay high while recall collapses to zero.

RInteractive R
set.seed(1) y <- rbinom(1000, 1, 0.02) # 2% positive pred <- rep(0, 1000) # always predict the majority accuracy <- mean(pred == y) recall <- sum(pred == 1 & y == 1) / sum(y == 1) round(c(accuracy = accuracy, recall = recall), 3)

  

  





Accuracy near 0.98 looks great, but recall is 0: the model never catches a single positive. Accuracy alone would have hidden that completely.







Run it: precision and recall from a threshold


Moving the cutoff



Score cases, then compute precision and recall at a chosen threshold. Lower the cutoff and watch recall rise while precision falls.




  

    
RInteractive R

    
set.seed(1)
y <- rbinom(400, 1, 0.3)
p <- pmin(pmax(0.3 * y + rnorm(400, 0.3, 0.2), 0), 1)   # scores, higher for positives
metrics <- function(t) {
  pred <- as.integer(p >= t)
  c(precision = sum(pred & y) / max(sum(pred), 1),
    recall    = sum(pred & y) / sum(y))
}
round(rbind(t_0.5 = metrics(0.5), t_0.3 = metrics(0.3)), 3)

    

      
      
    

    

  

  





Dropping the threshold from 0.5 to 0.3 catches more positives (higher recall) at the cost of more false alarms (lower precision), the trade-off you tune by cost.

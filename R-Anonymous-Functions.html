R Anonymous Functions in 2026: The \(x) Syntax That Replaces function(x)

An anonymous function is a function without a name — defined inline, used once, then discarded. R 4.1 introduced \(x) as a compact shorthand for function(x), giving R a clean lambda syntax that works everywhere.

Most R code uses named functions. But inside sapply(), lapply(), and purrr::map(), you often need a tiny function that exists for just one operation. That's an anonymous function. This tutorial shows you both syntaxes, when to use each, and how they work in base R and purrr.

Every code block below is interactive. Click Run to execute, edit to experiment, and Reset to restore the original.

What Is an Anonymous Function?

An anonymous function is a function you define right where you use it. You don't assign it to a variable. You don't call it later. It exists for one purpose: to do one job, right now.

R
# Named function — reusable double <- function(x) x * 2 cat("Named:", double(5), "\n") # Anonymous function — used once, inline result <- sapply(1:5, function(x) x * 2) cat("Anonymous:", result, "\n")

    

  





Both do the same math. The difference is intent. Name a function when you'll use it again. Keep it anonymous when it's a one-time operation.



The Two Syntaxes



The Traditional Way: function(x)



This has been in R since the beginning. It's clear, explicit, and everyone recognizes it:




  

    

      R
      

        
        
      

    

    
# Traditional anonymous function
sapply(1:5, function(x) x^2)

    

    

  





The New Way: \(x) (R 4.1+)



R 4.1 (released May 2021) introduced a shorthand. The backslash \ replaces the word function:




  

    

      R
      

        
        
      

    

    
# New shorthand — same result
sapply(1:5, \(x) x^2)

    

    

  





The \ was chosen because it looks like the Greek letter lambda (λ), which represents anonymous functions in computer science. These two are identical:




  

    

      R
      

        
        
      

    

    
# Side by side — these are the same
result1 <- sapply(1:5, function(x) x^2 + 1)
result2 <- sapply(1:5, \(x) x^2 + 1)

cat("function(x):", result1, "\n")
cat("\\(x):       ", result2, "\n")
cat("Identical?  ", identical(result1, result2), "\n")

    

    

  





Anonymous Functions in Base R



Base R's apply family — lapply(), sapply(), vapply(), and tapply() — all accept anonymous functions:




  

    

      R
      

        
        
      

    

    
# sapply — simplifies to vector when possible
cat("sapply:\n")
sapply(1:5, \(x) x^2 + 1)

# lapply — always returns a list
cat("\nlapply:\n")
lapply(c("hello", "world"), \(s) {
  paste0(toupper(substring(s, 1, 1)), substring(s, 2))
})

    

    

  





With vapply(), you specify the expected output type — similar to purrr's suffix system:




  

    

      R
      

        
        
      

    

    
# vapply — type-safe version of sapply
vapply(1:5, \(x) x > 3, logical(1))

    

    

  





Anonymous Functions in purrr



purrr's map() family works seamlessly with both syntaxes. See the purrr map() tutorial for the full guide.




  

    

      R
      

        
        
      

    

    
library(purrr)

# \(x) syntax — recommended
cat("\\(x) syntax:\n")
map_dbl(1:5, \(x) x^2)

# function(x) — still works fine
cat("\nfunction(x) syntax:\n")
map_dbl(1:5, function(x) x^2)

    

    

  





The Old Formula Syntax: ~.x



Before R 4.1, purrr had its own shorthand using ~ and .x:




  

    

      R
      

        
        
      

    

    
# purrr formula syntax (older style)
cat("Formula ~.x:\n")
map_dbl(1:5, ~.x^2)

# \(x) — modern standard R
cat("\n\\(x) syntax:\n")
map_dbl(1:5, \(x) x^2)

# For two arguments, formula used .x and .y
cat("\nTwo-argument formula:\n")
map2_chr(c("A", "B"), c(1, 2), ~paste(.x, .y))

cat("\nTwo-argument \\():\n")
map2_chr(c("A", "B"), c(1, 2), \(x, y) paste(x, y))

    

    

  





The formula syntax is purrr-only. The \(x) syntax is standard R. Prefer \(x) in new code.



Multi-Line Anonymous Functions



Anonymous functions can span multiple lines. Use curly braces {}:




  

    

      R
      

        
        
      

    

    
scores <- c(95, 72, 88, 41, 67)

grades <- sapply(scores, \(score) {
  if (score >= 90) return("A")
  if (score >= 80) return("B")
  if (score >= 70) return("C")
  if (score >= 60) return("D")
  return("F")
})

data.frame(score = scores, grade = grades)

    

    

  





If the function is this long, consider naming it instead. A named function is easier to test and appears in error tracebacks.



When to Name vs Keep Anonymous



Here's a simple decision rule:



Keep it anonymous when:


    

  • The body is one line
    • 

  • You use it in exactly one place
    • 

  • The operation is obvious from context
    • 




Name it when:


    

  • You use the same logic in multiple places
    • 

  • The function body is more than 2-3 lines
    • 

  • The operation needs explanation (the name IS the explanation)
    • 

  • You want to test it separately
    • 





  

    

      R
      

        
        
      

    

    
prices <- c(10, 25, 50, 75, 100)

# Good anonymous — obvious, short, one use
cat("With 8% tax:\n")
sapply(prices, \(p) p * 1.08)

# Better named — when logic is reused or complex
apply_tax <- function(price, rate = 0.08) {
  price * (1 + rate)
}

cat("\nWith custom tax function:\n")
sapply(prices, apply_tax)

cat("\nWith 10% rate:\n")
sapply(prices, apply_tax, rate = 0.10)

Passing Extra Arguments (No Lambda Needed)



You don't always need an anonymous function. If you just want to pass extra arguments to an existing function, many R functions forward ... for you:




  

    

      R
      

        
        
      

    

    
data <- list(c(1, NA, 3), c(4, 5, NA), c(NA, NA, 9))

# Unnecessary anonymous function
cat("With lambda:\n")
sapply(data, \(x) mean(x, na.rm = TRUE))

# Cleaner — pass the argument directly
cat("\nWithout lambda:\n")
sapply(data, mean, na.rm = TRUE)

    

    

  





This works because sapply() passes extra arguments through ... to the function. It's cleaner, but only works when the extra arguments are the same for every element.



Immediately Invoked Function Expressions (IIFE)



You can define and call an anonymous function in one step. This is called an IIFE (pronounced "iffy"):




  

    

      R
      

        
        
      

    

    
# Define and call in one step
result <- (\() {
  data <- 1:100
  cleaned <- data[data > 10 & data < 90]
  mean(cleaned)
})()

cat("Result:", result, "\n")

# The variables data and cleaned don't exist here
cat("'data' exists in global env?", exists("data"), "\n")

    

    

  





This pattern creates a temporary scope — the variables data and cleaned don't leak into your environment. It's useful in scripts but rare in practice.

FAQ



Is \(x) just syntactic sugar?



Yes. It compiles to exactly the same thing as function(x). There is zero performance difference. They produce identical bytecode.



Do I need R 4.1 to use \(x)?



Yes. If you're writing code for others who might use older R versions, stick with function(x). In 2026, most R installations support it.



Can I use \(x) in R packages?



Yes, as long as you declare Depends: R (>= 4.1.0) in your DESCRIPTION file.



Why not use ~ in purrr anymore?



The ~.x formula syntax works, but it's purrr-specific. The \(x) syntax is standard R that works everywhere — in base R, purrr, data.table, and any other package. One syntax to learn, one syntax to use.



Do anonymous functions show up in error tracebacks?



Not clearly. If you're debugging, named functions are easier to locate in a stack trace. This is one reason to name complex functions even if you only use them once.



Conclusion



Anonymous functions are functions without names, used inline for one-time operations. R 4.1 gave us \(x) as a shorter alternative to function(x). Use the short form for simple, obvious transforms. Name your function when it's complex, reused, or needs debugging. And if you see ~.x in old purrr code, know that \(x) is the modern replacement. For more on how anonymous functions fit into functional programming, see the purrr map() tutorial and function factories.

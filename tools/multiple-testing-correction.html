Multiple Testing Correction

All five methods, side by side · Bonferroni, Holm, Hochberg, BH (FDR), BY · Smart paste from CSV, TSV, or newlines · R code emitted alongside

When you run many tests, the chance of seeing a false positive somewhere goes up. Paste your p-values; we'll compare five correction methods side by side and recommend which fits your situation. Most tools just compute one — we show you the trade-off so you can pick on purpose.

How multiple testing correction works Primer · 4 min
In this primer 01What it is 02How it works 03What you put in 04What you get out 05How to interpret 06When to use 07Pitfalls
What it is

If you run one statistical test, there's a small chance (usually 5%) you'll see a "significant" result by pure luck — even when nothing real is happening. Run 20 tests at once, and that small chance adds up. You'd expect 1 false alarm just from luck. Run 100 tests, expect 5. The more you look, the more "findings" you'll see that aren't real.

Multiple testing correction is the fix. It adjusts your p-values (or your significance threshold) so the chance of being fooled stays under control, no matter how many tests you ran.

How it works

Think of it like flipping a coin 20 times. Even with a fair coin, you might see a streak of 5 heads. That streak isn't evidence the coin is rigged — it's just what happens when you flip enough times. Statistical tests work the same way.

Two strategies depending on caution: FWER methods (strict) — Bonferroni, Holm — control the chance of any false alarm. FDR methods (looser) — Benjamini-Hochberg, BY — control the fraction of discoveries that are false. FWER for confirmatory work; FDR for exploratory.

What you put in

A list of p-values from your tests. Paste them however you have them — one per line, comma-separated, scientific notation (1.2e-5). Optionally pick the strictness level (default 5%) and indicate whether tests are correlated or independent.

What you get out

An adjusted p-value for each input, under all four methods, side-by-side. p_adj < 0.05 means "significant even after correction." We flag which tests survive each method so you can see the trade-off — Bonferroni is strict and may flag nothing; BH usually keeps more.

How to interpret it in practice

The tests that survive correction are your real findings. Don't talk about the rest as "trends" — they failed; that's the point.

"3 out of 50 tests survive Holm" tells a very different story from "11 raw p-values were below 0.05" — same data, different headline. Always say how many tests in the family and which method.

If almost nothing survives Bonferroni but BH gives you a list, that's not a reason to switch after the fact — it's a signal you're in exploratory FDR territory, not confirmatory FWER. Decide before looking.

When to use this

A/B testing many variants. Comparing many subgroups (region × age × device). Genomics — testing thousands of genes. Brain imaging — every voxel is a test. Marketing dashboards with many KPIs. Feature screening in machine learning. Anywhere you'd otherwise be tempted to "find" significance by trying enough things.

Common pitfalls

Choosing the family after looking at the data. "Only correct over the 5 tests that look significant" defeats the whole purpose. Decide first.

Reporting raw p-values when you ran a family. A raw p = 0.04 means very different things if you ran 1 test versus 50.

Bonferroni when FDR fits better. In genomics and large screens, Bonferroni leaves real findings on the table. Mixing pre-registered with exploratory. Keep them separate.

MethodsWhen to use which method

Bonferroni
controls family-wise error rate
The strictest. Multiplies each p by m (number of tests). Use when even one false positive matters — small confirmatory studies, regulatory submissions.
Holm
controls FWER · uniformly more powerful than Bonferroni
Step-down: orders p-values, applies decreasing strictness. Same FWER guarantee as Bonferroni but rejects more tests. Default choice for confirmatory.
Hochberg
controls FWER · slightly more powerful · independence assumed
Step-up version of Holm. Slightly more powerful but requires the tests to be independent or positively dependent. Safe in most applied work.
BH (Benjamini–Hochberg)
controls false-discovery rate
The standard for screening. Allows a small fraction of false positives in exchange for much higher power. Use when you have many tests and expect most to be null. Recommended default for exploratory work.
BY (Benjamini–Yekutieli)
controls FDR under dependence
A more conservative BH that holds even when tests are arbitrarily dependent. Use when correlations between tests are strong (e.g., genes in the same pathway).

ReferenceAnatomy of the answer

FWER = P(≥ 1 false positive across family)
Family-wise error rate. Probability of *any* false positive across the family. Bonferroni and Holm control this. If you can't tolerate even one false positive, use these.
FDR = E[ V / max(R, 1) ]
(V = false rejections, R = total rejections)
False discovery rate. Expected fraction of false positives among tests you call significant. BH and BY control this. With 100 tests and FDR=0.05, ~5% of significant results may be false — more powerful than FWER for screens.
reject if adj_p ≤ α
Adjusted p-values. Computed so that adj_p ≤ α is the rejection rule. Monotonicity is enforced; min(1, …) is applied so adjusted p never exceeds 1. Same convention as R's p.adjust.
verified vs p.adjust to 8 decimals
Cross-checked. Output matches R's p.adjust(method=) across ≥ 30 input vectors and all 5 methods.

AlternativesWhen this is the wrong tool

If you have…
Use instead
One primary and many secondary tests
Fixed-sequence or hierarchical procedure (Maurer-Bretz) — blanket correction over-corrects.
Hierarchical / structured tests (e.g., genomic regions)
Group-FDR or hierarchical FDR (Yekutieli, Heller) — better power for structured families.
Prior knowledge of which tests are more likely true
Weighted procedures (Genovese-Roeder) — incorporate priors.
You're picking the method after seeing the corrected p-values
Stop. Pick the method first; data go through it. The other order is p-hacking.
Need Storey's q-value (more powerful BH variant)
qvalue::qvalue() in R — not implemented here.

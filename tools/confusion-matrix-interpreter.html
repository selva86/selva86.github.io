Confusion Matrix Interpreter

Binary or multi-class · All metrics + which one to trust when · Runs in your browser

Enter a 2×2 (or k×k) confusion matrix; we compute every metric — accuracy with 95% CI, sensitivity, specificity, precision, F1, MCC, Cohen's κ, balanced accuracy, LR+/LR− — translate them into plain English, and tell you which one to trust based on imbalance and which kind of error is more costly.

Worked examples
🩺 Rare disease screening

A diagnostic screen with 2% disease prevalence. The classifier looks accurate at first glance (95%), but balanced accuracy and MCC tell a much more sober story.

📐 What you'll see: Accuracy = 95%, but most positives are missed. Recall ≈ 50%, MCC ≈ 0.25 — accuracy is misleading at extreme imbalance.
How confusion matrix metrics work
What it is

You've built a classifier — a model that predicts a category. Now you need to know how good it is. A confusion matrix is the simplest way to summarize: a table of "predicted vs. actual" counts.

For a yes/no classifier, the table has four cells:

• True Positive (TP): model said "yes," and it really was yes ✓
• False Positive (FP): model said "yes," but it was actually no ✗
• False Negative (FN): model said "no," but it was actually yes ✗
• True Negative (TN): model said "no," and it was indeed no ✓

From those four numbers you can compute every standard metric — accuracy, precision, recall, F1, and so on. Each metric tells a different story. Picking the right one matters, especially when one class is much rarer than the other.

How it works

Each metric answers a different question:

• Accuracy = "what fraction did I get right overall?" (TP + TN) / total. Simple, but can be misleading with imbalanced classes.
• Precision = "when I said yes, was I right?" TP / (TP + FP)
• Recall (sensitivity) = "when it was really yes, did I catch it?" TP / (TP + FN)
• F1 = a balance between precision and recall. Penalizes imbalance between them.
• MCC (Matthews Correlation) = a single robust score from −1 to +1. Best one-number summary when classes are skewed.
• Specificity = "when it was really no, did I correctly say no?"
• Cohen's κ = "how much better than random guessing?"

What you put in

Either:

• Type the counts directly into a 2×2 (or k×k for multi-class) grid
• Paste the output from caret::confusionMatrix() in R

For binary classification, pick which class is "positive" — that affects asymmetric metrics like precision and recall.

What you get out

• Every metric, color-coded (good / warning / bad)
• A "which metric to trust here" decision tree that highlights the right metric based on your imbalance and error costs
• Warnings for imbalanced classes, suspicious 100% accuracy (often data leakage), worse-than-chance performance
• For multi-class: per-class metrics plus macro and weighted averages

How to interpret it in practice

Which metric should you trust? Depends on two things: how balanced your classes are, and which error costs more.

Balanced classes (close to 50/50):
Accuracy + F1 is fine. Both error types are equally costly, both classes are equally common.

Imbalanced classes (one class < 20%):
Ignore accuracy — it lies. A classifier that always predicts the majority class on 99%-prevalence data scores 99% accuracy and is completely useless. Report MCC + balanced accuracy + per-class precision/recall instead.

False positives are expensive (spam blocking real email; biopsies on healthy patients):
Emphasize precision. Use F0.5 (precision-weighted F).

False negatives are expensive (missing a cancer; missing fraud):
Emphasize recall. Use F2 (recall-weighted F).

If accuracy is suspiciously close to 100%, hunt for a bug. Usual culprits: evaluating on the training set, a feature that's secretly a copy of the label, or duplicate rows between train and test. Real classifiers almost never score 100% on truly held-out data.

When to use this

Any classification task once you have predicted labels and true labels for a test set:

• Spam detection
• Medical screening / diagnostics
• Fraud detection
• Image classification
• Churn prediction
• Sentiment analysis

The model can be logistic regression, random forest, gradient boosting, a neural network, or GPT — the evaluation is the same.

Common pitfalls

Trusting accuracy on imbalanced data. The most common rookie mistake — and often the most expensive in production.

Optimizing one metric to the exclusion of others. You can trivially get 100% recall by predicting everything as "yes" — but precision tanks. Watch both.

Forgetting AUC needs probabilities, not just labels. A confusion matrix is at one threshold. AUC integrates over all thresholds and can't be computed from a single matrix.

Reporting test results from data the model was tuned on. Use a held-out set you didn't touch during training or hyperparameter selection.

    Anatomy of the metrics
    
  
    
    
    accuracy = (TP + TN) / N
    
    
    Accuracy. Fraction of all predictions that are correct. The 95% CI uses the Wilson score interval — narrower and better-behaved than a normal-approximation interval, especially near 0% or 100%.
    
  
    
  
    
    
    precision = TP / (TP + FP)
recall    = TP / (TP + FN)
F1        = 2·precision·recall / (precision + recall)
    
    
    Precision and recall. Precision answers "when the model says positive, is it right?"; recall answers "of the actual positives, how many did we catch?". F1 is their harmonic mean — penalises imbalance between the two. Use F0.5 when precision matters more, F2 when recall does.
    
  
    
  
    
    
    MCC = (TP·TN − FP·FN) /
       √((TP+FP)(TP+FN)(TN+FP)(TN+FN))
    
    
    Matthews Correlation Coefficient. A correlation between predicted and actual labels — ranges from −1 (perfectly wrong) through 0 (random) to +1 (perfect). Robust to class imbalance; the single best one-number summary when classes are skewed.
    
  
    
  
    
    
    κ = (po − pe) / (1 − pe)
    
    
    Cohen's κ. Agreement beyond chance. po = observed agreement (= accuracy); pe = expected agreement under independent margins. Landis & Koch: 0–0.2 slight, 0.2–0.4 fair, 0.4–0.6 moderate, 0.6–0.8 substantial, > 0.8 almost perfect.
    
  
    
  
    
    
    LR+ = sensitivity / (1 − specificity)
LR− = (1 − sensitivity) / specificity
    
    
    Likelihood ratios. Used in diagnostic medicine to update pre-test probability into post-test probability. LR+ > 10 is "strong evidence for the disease"; LR− < 0.1 is "strong evidence against." Independent of prevalence — that's their charm.

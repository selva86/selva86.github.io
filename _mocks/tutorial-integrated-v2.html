R Data Types: Which Type Is Your Variable?

R has six basic data types, numeric, integer, character, logical, complex, and raw, and the type of a value decides what you can do with it. Get it wrong and your math turns into string concatenation, your filters return nothing, or your model silently drops rows.

#What are R's six data types?

Before you can trust a number, you need to know whether R actually sees it as a number. Every value in R belongs to exactly one of six basic types, and one call to class() tells you which. From here on, each type gets its own colour.

numeric integer character logical complex raw

Six values, six different types. weight is numeric because 72.5 has a decimal. age is integer only because we added the L suffix, without it R would store 30 as numeric too. name is character (always quoted). is_raining is logical. signal is complex. byte is raw. That is the whole family.

#How do I check a variable's type?

Knowing the types exist is one thing; checking them in running code is another. R gives you two families of tools: class() returns the type as a string, and the is.*() functions return TRUE or FALSE for a specific type. Use class() when you want to know which type a value is, and is.numeric() / is.character() when you want to test if it is a particular type inside an if statement.

The last line is the trap every beginner hits. "72.5" looks like a number but it is wrapped in quotes, so R stores it as character. This is exactly why data read from a CSV with a single stray non-numeric cell comes in as character.

#class(), typeof(), and mode()

R has three functions that all seem to answer "what type is this?" and they disagree just often enough to confuse. The rule: class() tells you the object's high-level class (what it behaves like), typeof() tells you how R stores it internally, and mode() is a legacy category you will rarely need.

Key insight

class() tells you what an object acts like; typeof() tells you how R stores it. A data frame has class "data.frame" but typeof "list", because internally a data frame is a list of columns. Knowing this is how you debug "why doesn't my function work on this object?" bugs.

#Why numeric really means "double"

When most languages say "number" they mean integer. R flips that: every number you type is a double (a 64-bit floating-point number) unless you explicitly ask for an integer with the L suffix. This matters more than it sounds, because doubles and integers behave differently at extremes.

Tip

Use the L suffix only when you genuinely need an integer and you won't overflow. Integer storage is half the memory of double (4 bytes vs 8), which matters for vectors of millions of counts or IDs. For casual scripting, let R default to double.

#How does R coerce types automatically?

R will not let values of different types sit side-by-side in one vector, everything in c(...) must share a single type. When you mix them, R silently coerces them all up a strict ladder: logical → integer → double → complex → character. Character always wins, because any value can be written as text. That single "three" turned the other two numbers into strings, and sum() now throws an error. This is the single most common "my CSV won't add up" bug in R. Coercion also works the other way: when logicals meet arithmetic, R promotes TRUE to 1 and FALSE to 0, which is how sum() counts matches and mean() gives a proportion.

Key insight

Coercion is silent, which is what makes it dangerous. R won't warn you that your vector of numbers became a vector of strings, you only find out when arithmetic breaks downstream. Whenever a calculation returns an unexpected result, class() your inputs first.

#NA, NULL, NaN, and Inf

Not every value in R is a regular type, some represent "missing", "nothing", or "impossible." The four special values are NA (missing), NULL (absent), NaN (not a number), and Inf (infinity). They look similar but behave very differently.

Warning

is.na(NULL) returns logical(0), not FALSE. Because NULL has zero length, is.na() returns a zero-length logical, which can crash if statements. Always use is.null() for NULL checks and is.na() for NA checks. Never mix them up.

#Which type should I use when?

With six types the decision is usually obvious. If the value is text, use character; if it is TRUE/FALSE, use logical; if it is a whole number that will never go near two billion, integer saves memory; otherwise use numeric. Complex and raw are specialist types, you will know when you need them.

Note

Prefer character over factor for free-text columns, and remember the raw type is rare in day-to-day R, you will meet it mostly when reading binary files or doing cryptography. If you are not sure you need raw, you don't.

#Putting it all together

A tiny weather log that uses four types correctly, and then the contamination bug beginners hit constantly.

Each column got the right type the first time: character for free text, numeric for measurements, logical for flags, integer for IDs. The moment one temperature is read as "--" from a broken sensor, the whole column turns character and mean() returns NA. That is the silent coercion bug, in the wild.

#Summary

TypeExampleclass()typeof()When to use
numeric72.5"numeric""double"Default for any number, measurements, money
integer30L"integer""integer"Counts, IDs, indexes, saves memory
character"Selva""character""character"Any text, names, labels
logicalTRUE"logical""logical"Flags, comparisons, filter masks
complex1 + 2i"complex""complex"Signal processing, rare in stats
rawas.raw(255)"raw""raw"Binary files, bytes, specialist

The three rules that catch 90% of type bugs:

  1. Check before you calculate. class() and typeof() are your friends; use them whenever something feels off.
  2. One bad cell contaminates the whole vector. Mix a string in with numbers and R silently turns everything character.
  3. Doubles are the safe default; integers are an optimization. Only reach for L when you have millions of counts and memory matters.

A free test set

Out-of-bag error

Remember the ~37% of rows each tree never saw (its bootstrap left them out)? Here's the payoff. To score the forest, run every row through only the trees that didn't train on it, and average. No data held back, no separate test split needed.

Why this is a big deal

OOB error is an honest, almost-free estimate of test performance, computed during training. On most problems it lands very close to a proper cross-validation, for a fraction of the work.

It's the number you'll watch while tuning, in a moment, on a live forest.

In R

Train one in five lines

The ranger package fits a fast forest and reports OOB error directly. This is the whole training step for a churn model:

Rforest.R
library(ranger)
set.seed(42)
rf <- ranger(
  churned ~ .,            # predict churn from all columns
  data        = train,
  num.trees   = 500,         # more is safer, never overfits
  mtry        = 3,           # features tried per split (~sqrt p)
  importance  = "impurity"   # so we can rank features later
)
rf$prediction.error       # the out-of-bag error
#> [1] 0.115
# 11.5% OOB error -> 88.5% accuracy, no test set used

Two numbers in that call decide everything: num.trees and mtry. Let's feel what they do.

The only knobs worth turning

That curve hides almost no surprises, which is exactly why forests are so usable:

1
num.trees: more is safe
Error falls then flattens. Use as many as you can afford (300 to 1000). Extra trees never overfit, they just cost time.
2
mtry: the one real dial
Too low starves each tree; too high re-correlates them. Start near √p for classification (p/3 for regression) and search a small range around it.
3
min.node.size: light touch
Larger values grow shallower trees. The default is usually fine; nudge it only if a forest is overfitting a small, noisy dataset.

Reading the forest

Which features mattered?

Because every tree records how much each split improved purity, a forest can rank features for free. Sum those gains across all trees and you get variable importance, the first thing to look at after training.

Variable importance (impurity), churn forest
Read it with care

Importance says a feature was useful for splitting, not that it causes the outcome, and impurity importance can inflate high-cardinality features. For decisions that matter, confirm with permutation importance or SHAP.

Check yourself

Quick question

You raise num.trees from 100 to 500 and the OOB error barely moves. What does that tell you?

Right. Past convergence, more trees neither help nor hurt accuracy, they just cost time. And error won't reach zero: it settles at the forest's irreducible level for this data and mtry.
Not quite. A flat curve means the forest has converged. More trees won't hurt (forests don't overfit in num.trees), but they won't drive error to zero either, that floor is set by the data and mtry.
Know your tool

Where forests shine, where they don't

A random forest is the strongest model you can train with almost no tuning. But it isn't magic, and knowing the edges is what separates a practitioner from a button-pusher.

Strengths
  • Strong accuracy out of the box, minimal tuning
  • Handles mixed numeric and categorical features
  • Robust to outliers and irrelevant features
  • Free OOB error and feature importance
Limits
  • Less interpretable than a single tree
  • Can't extrapolate beyond the training range
  • Big models are memory-heavy and slower to predict
  • Gradient boosting often edges it out when tuned

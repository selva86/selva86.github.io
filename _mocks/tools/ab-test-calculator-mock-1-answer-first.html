iNew to A/B testing? Read the 4-minute primer

What it is. An A/B test routes traffic to two variants of the same thing (page, email, button), measures a binary outcome (converted? clicked?), and asks whether B’s true conversion rate differs from A’s, or whether the gap you saw is the kind of jitter you would expect from random sampling.

How to read it. Four numbers do most of the work. Lift is B minus A in percentage points (or relative percent). p-value is the chance of seeing a gap this big when there really is no difference. 95% CI for the lift is the range of differences the data are compatible with: if it crosses zero, you cannot rule out “no effect”. BF10 is a Bayes factor: above 10 is strong evidence for B, below 1/10 strong evidence for A.

Frequentist vs Bayesian. Frequentist: pre-set alpha and power, run to a fixed sample size, decide on p < alpha. Bayesian: start from a prior (uniform Beta(1,1) is fine), update each arm to a Beta posterior, report P(B > A) and the credible interval for the lift. Both answer the same business question; the math and the assumptions differ.

Picking the mode. Have not run yet? Use Plan to size the experiment from a baseline rate, a minimum lift, and your desired power. Already done? Use Analyze with the per-arm visitors and conversions. The framing toggle controls which numbers show up.

Anatomy of an A/B test the math, 5 steps
Two-proportion z-test (frequentist): p_pool = (c_a + c_b) / (n_a + n_b) SE_0 = sqrt( p_pool (1 - p_pool) (1/n_a + 1/n_b) ) z = (p_b - p_a) / SE_0 p = 2 (1 - Φ(|z|))
Two-proportion z-test. Pool the two arms under H0 to estimate one shared rate, compute the standard error from that pooled rate, and read off a z-statistic. The 95% CI for the lift uses the unpooled SE so the interval centers on the observed gap. Matches prop.test(..., correct = FALSE).
Bayesian beta-binomial conjugate: prior: p_a, p_b ~ Beta(α₀, β₀) posterior: p_a ~ Beta(α₀+c_a, β₀+n_a-c_a) output: P(p_b > p_a), 95% CrI for p_b - p_a
Beta-Binomial conjugate. A Beta prior is conjugate to the Binomial, so the posterior is Beta in closed form. We sample 10,000 draws from each posterior, count the fraction where p_b exceeds p_a, and take the 2.5th/97.5th percentiles of the lift draws.
Sequential / alpha-spending: each interim look at fraction t of N spend α_t such that sum α_t = α (Pocock)
Sequential alpha-spending. If you peek K times and stop early on a significant look, your real false-positive rate is far above alpha. Group-sequential designs (Pocock, O’Brien-Fleming) spread alpha across looks so family-wise error stays controlled.
Sample size (two-prop, Cohen's h): h = 2 (arcsin √p2 - arcsin √p1) n_per_arm = (z_α + z_β)² / h²
Sample size for proportions. The arcsine transform stabilizes variance (Cohen’s h). Plug baseline p1, minimum-detectable p2, alpha and power, and the formula returns n per arm at 50/50. For unequal splits, scale total by 1/(4k(1-k)). Matches pwr.2p.test().
Lift, RR, absolute difference: absolute lift = p_b - p_a (pp) relative lift = (p_b - p_a) / p_a risk ratio = p_b / p_a
Lift vs RR vs absolute. “B is 20% better” is ambiguous: 10% rising to 12% is +2pp absolute, +20% relative, RR = 1.20. CIs and BF10 here are on the absolute scale; the recap shows the relative figure for stakeholders.
When this is the wrong tool 6 alternatives
If you have…
Use instead
Three or more variants
Multi-armed bandit (Thompson sampling), or Bonferroni / Holm over pairwise z-tests.
Continuous outcome (revenue, time-on-page)
Welch’s two-sample t-test. The two-proportion test forces a binary outcome.
Survival / time-to-event
Kaplan-Meier with log-rank, or Cox proportional hazards. Censoring breaks the binomial.
Repeated measures on the same user
Paired test (McNemar / paired t), or mixed-effects model with user random intercept.
Ratio metrics (clicks-per-visit)
Delta-method or bootstrap CI for the ratio. The denominator is random per user.
You peeked early and stopped on a significant look
Group-sequential (alpha-spending) up front, or always-valid sequential intervals (mSPRT).

The idea

The wisdom of crowds

Ask one noisy expert and you get a noisy answer. Ask hundreds and average them, and the random errors cancel while the real signal survives. That is the whole trick behind a forest.

Var( average of B trees ) = σ² / B
If each tree has variance σ² and the trees are independent, averaging B of them divides the variance by B. More trees, steadier predictions.

The catch is hiding in one word: independent. Hold that thought, we'll come back to it.

The catch

Clones don't help

Averaging only cancels errors if the trees make different mistakes. Grow a hundred identical trees and their average is just... that same tree. No variance reduction at all.

So the real engineering problem of a random forest is: how do we force the trees to be different on purpose? There are two tricks, and a forest uses both.

Trick 1

Give each tree different data

Before growing a tree, draw a bootstrap sample: pick rows from the training set at random with replacement, until you have a set the same size. Some rows appear twice, others not at all.

A free gift

On average each bootstrap leaves out about 37% of the rows. A tree never sees its left-out rows, so they make a built-in test set for that tree. Those are the out-of-bag rows, and they power the free OOB error you'll meet in Lesson 3.

Different data in means a different tree out. But there's a sneakier source of sameness left to kill.

Trick 2, the motivation

Bootstrap isn't enough

Suppose one feature, say tenure, is much more predictive than the rest. Then every tree, even on its own bootstrap sample, will choose tenure for its very first split. The trees end up looking nearly identical near the top.

Statisticians call this correlation between the trees, and it's poison for averaging: remember σ²/B only holds when the trees are independent. Correlated trees barely reduce variance.

The trick that names it

Random features

Here's the fix that makes it a random forest: at each split, the tree may only consider a random handful of features, not all of them. The dominant feature can't win every time, so the trees diverge. Toggle below and watch what each tree picks for its first split.

Quick question

Why does a random forest let each split consider only a random subset of the features?

Exactly. Restricting features stops the dominant one from winning every split, so the trees disagree more. Independent-ish trees are what let averaging drive σ²/B down. Individual trees actually get a touch weaker, the forest gets stronger.
Not quite. Each tree actually gets slightly weaker. The point is to decorrelate the trees, uncorrelated errors cancel better when averaged.
Putting it together

The whole forest, in three rules

That's it. A random forest is just these three ideas stacked:

1
Bootstrap
Grow each tree on its own random resample of the rows.
2
Random features
At each split, only consider a random subset (mtry) of the features.
3
Average
Let all the trees vote; the majority (or mean) is the forest's answer.
Why it's so reliable

Each tree is a low-bias, high-variance learner. Bootstrap + random features make them diverse; averaging cancels the variance. You keep the low bias and throw away most of the variance, with almost no tuning.

Conditional Power & Sample Size Re-Estimation in R

Conditional power answers a hard mid-trial question: given what we have seen so far, how likely are we to still reject the null at the final analysis? Sample size re-estimation (SSR) uses that answer to top up enrollment when the interim look is promising but underpowered, without inflating the Type I error rate. In R, gsDesign::ssrCP() turns this into a reproducible, pre-specified workflow.

What is conditional power and why does it matter?

You have enrolled half your trial and the interim Z-statistic is 1.4, encouraging but well below the critical value of 1.96. Is the trial worth finishing as planned, or is it already a lost cause? Conditional power puts a probability on that question by projecting the final result forward from what you have already observed. One call does the math.

We build a two-stage group sequential design anchored to a fixed-sample size of 128 (the sort of number pwr.t.test() gives you for an 80%-power, d = 0.5 study), then ask condPower() for the conditional power at the interim.

RConditional power at the interim look
library(gsDesign) library(mvtnorm) # Two-stage design: fixed N of 128 total, interim at 50% information design_gs <- gsDesign(k = 2, n.fix = 128, timing = 0.5, alpha = 0.025, beta = 0.20, test.type = 1) design_gs$n.I # cumulative sample size at each look #> [1] 67.83 135.65 cp_interim <- condPower(z1 = 1.4, n2 = design_gs$n.I[2] - design_gs$n.I[1], x = design_gs) round(cp_interim, 3) #> [1] 0.517

  

  





The trial is not dead at Z1 = 1.4, but conditional power of about 52% is well below the 80% target we planned for. That gap between "ongoing chance" and "planned chance" is the cue to consider SSR. If CP were 10%, we would stop for futility; if CP were 90%, we would keep going unchanged; at 52%, we are in the zone where adding patients can rescue the study.



Key Insight
Conditional power reads the middle of a trial the way a weather nowcast reads the sky. It is a probabilistic update given the interim data, not a commitment and not a new hypothesis test.

How is conditional power calculated from the interim Z?



The formula projects the final Z forward. Given the interim Z1, it asks: what is the probability that the final Z will exceed the critical value, assuming some effect size θ for the remaining patients?



$$\text{CP}(\theta) = 1 - \Phi\!\left(\frac{z_\alpha\sqrt{I} - z_1\sqrt{I_1} - \theta (I - I_1)}{\sqrt{I - I_1}}\right)$$



Where:



    


  • $z_1$ = the observed interim standardized statistic
    • 


  • $I_1$ = statistical information at the interim (proportional to stage-1 sample size)
    • 


  • $I$ = total information at the final analysis
    • 


  • $\theta$ = assumed effect size for the remaining (second-stage) data
    • 


  • $z_\alpha$ = final-analysis critical value (about 1.96 for α = 0.025 one-sided)
    • 





The only unknown once the interim data are in is θ. Let's rebuild the calculation in base R so you can see exactly what condPower() is doing under the hood, then verify the two match.




  

    
RManual CP function in base R

    
# Reusable helper: CP at z1 given information levels and assumed theta
cp_manual <- function(z1, info1, info_final, theta, z_alpha = qnorm(0.975)) {
  numerator   <- z_alpha * sqrt(info_final) -
                 z1 * sqrt(info1) -
                 theta * (info_final - info1)
  denominator <- sqrt(info_final - info1)
  1 - pnorm(numerator / denominator)
}

# For a 2-sample mean test with SD=1, info = n / 4
info1       <- 64 / 4     # 16
info_final  <- 128 / 4    # 32
theta_plan  <- (qnorm(0.975) + qnorm(0.80)) / sqrt(info_final)  # planned effect
round(theta_plan, 3)
#> [1] 0.495

cp_base <- cp_manual(z1 = 1.4, info1 = info1, info_final = info_final,
                     theta = theta_plan)
round(cp_base, 3)
#> [1] 0.729

    

      
      
    

    

  

  





Under the planned effect size, CP at Z1 = 1.4 is about 73%. That is noticeably higher than the ~52% we got earlier from condPower(), and the reason is the default θ. condPower() uses the observed interim effect, which at Z1 = 1.4 is smaller than what we planned for. Different θ, different answer.



Note
Three common choices for θ. (1) The originally planned effect (optimistic, keeps the trial on its design assumptions). (2) The observed interim effect (realistic but noisy, biases CP toward 50%). (3) A blend, for example halfway between the two. Regulators usually want the rule pre-specified.




  

    
RCP across three theta choices

    
# Observed interim effect for a 2-sample z-test: theta_hat = z1 / sqrt(info1)
theta_obs   <- 1.4 / sqrt(info1)                  # ~0.35
theta_blend <- (theta_plan + theta_obs) / 2       # halfway

cp_table <- data.frame(
  choice   = c("planned", "observed", "blend"),
  theta    = round(c(theta_plan, theta_obs, theta_blend), 3),
  CP_at_z1 = round(sapply(c(theta_plan, theta_obs, theta_blend),

Same interim data, same design, three defensible answers: 0.73, 0.51, or 0.63. This is not a bug, it is the central subjective choice in CP. Writing which θ you will use into the protocol before the interim look is what keeps the analysis honest.

When should you re-estimate sample size (the promising zone)?



Chen, DeMets and Lan (2004) partitioned the interim into three zones based on CP. Only the middle zone justifies SSR, the other two call for different decisions.






Figure 1: Three conditional power zones that drive the SSR decision.



The unfavorable zone (CP < 0.3) is futility territory, the signal is too weak to salvage with a few extra patients. The promising zone (0.3 ≤ CP ≤ 0.8) is where SSR buys meaningful power for reasonable cost. The favorable zone (CP > 0.8) means the trial is already on track, extra enrollment is wasted.




  

    
RClassify interim Z into CP zones

    
decide_ssr <- function(z1, info1, info_final, theta,
                       lo = 0.3, hi = 0.8) {
  cp <- cp_manual(z1, info1, info_final, theta)
  zone <- cut(cp, breaks = c(-Inf, lo, hi, Inf),
              labels = c("unfavorable", "promising", "favorable"))
  data.frame(z1 = z1, CP = round(cp, 3), zone = zone)
}

z1_grid  <- c(0.5, 1.0, 1.4, 1.7, 2.0, 2.3)
zone_df  <- decide_ssr(z1 = z1_grid, info1 = info1,
                       info_final = info_final, theta = theta_plan)
zone_df
#>    z1    CP         zone
#> 1 0.5 0.183  unfavorable
#> 2 1.0 0.466    promising
#> 3 1.4 0.729    promising
#> 4 1.7 0.874    favorable
#> 5 2.0 0.956    favorable
#> 6 2.3 0.988    favorable

    

      
      
    

    

  

  





At Z1 = 1.4 we sit solidly in the promising zone, which is exactly where SSR rules are designed to act. At Z1 = 0.5 we would stop for futility, no amount of extra recruitment can close that gap at acceptable cost. At Z1 ≥ 1.7 the trial is already strong enough, adding patients only inflates cost.



Warning
Re-estimating outside the promising zone often doubles cost for little power gain. Worse, some ad-hoc rules (for example, re-estimate whenever CP < 0.5 using the observed effect) can inflate the Type I error rate above the nominal α unless paired with a combination test.

How does ssrCP() run a full re-estimation?



Everything above sets up the decision rule. ssrCP() from gsDesign puts the rule into a single call that adapts stage-2 sample size across a range of interim Z values, capped by a user-chosen maximum fold-increase.






Figure 2: End-to-end sample size re-estimation workflow with gsDesign.



The workflow plugs three choices into one function: a base group sequential design (carries the alpha-spending rules), a grid of possible interim Z values, and SSR parameters (maxinc caps the fold-increase, cpadj sets the promising zone, z2 selects the combination test).




  

    
RRun ssrCP across a grid of interim Z

    
# Keep the same base design; adapt only when CP is in the promising zone
ssr_result <- ssrCP(
  x      = design_gs,
  z1     = seq(0, 3, 0.25),
  maxinc = 2,                # cap stage-2 at 2x planned
  cpadj  = c(0.3, 0.8),      # promising zone bounds
  beta   = 0.20,             # target CP for re-estimation
  z2     = z2NC              # inverse-normal combination test
)

How do combination tests protect Type I error after re-estimation?



Here is the subtle problem. Once you adapt N based on interim data, the naive final Z-statistic is no longer distributed as standard normal under the null. Using it at α = 0.025 inflates the actual Type I error. Combination tests fix this by pre-committing to a weighting scheme for Z1 and Z2 that is mathematically invariant to the adaptation.



gsDesign ships three:







Function
Combines Z₁ and Z₂ via
When to prefer






z2NC
Inverse-normal: weighted sum with fixed weights
Default; well-understood and regulator-friendly




z2Z
Sufficient-statistic (naive) Z
Only when N is not adapted (as a sanity baseline)




z2Fisher
Fisher p-value combination: chi-squared on log p
Robust to small second stages, rarely used in SSR








  

    
RCompare stage-2 critical values across combination tests

    
# For the same interim Z1, what Z2 is required to reject at final?
z1_fix <- 1.4
z2_nc     <- z2NC(z1 = z1_fix, x = design_gs)
z2_z      <- z2Z(z1 = z1_fix, x = design_gs,
                 n2 = design_gs$n.I[2] - design_gs$n.I[1])
z2_fisher <- z2Fisher(z1 = z1_fix, x = design_gs)

data.frame(test = c("z2NC", "z2Z", "z2Fisher"),
           z2_required = round(c(z2_nc, z2_z, z2_fisher), 3))
#>       test z2_required
#> 1     z2NC       1.198
#> 2      z2Z       1.198
#> 3 z2Fisher       1.473

    

      
      
    

    

  

  





Inverse-normal (z2NC) and sufficient-statistic (z2Z) agree when no adaptation happens. Once you adapt N, the two diverge: z2NC keeps its weight scheme fixed (protecting α), z2Z does not. z2Fisher takes a different route entirely, combining p-values rather than Z-statistics.



Key Insight
Combination tests do not make the data better. They pre-commit to a weighting scheme so the final decision rule was fixed before you ever looked at interim data. That pre-commitment is what preserves α through any SSR rule that respects the weights.

What could go wrong with sample size re-estimation?



SSR is a powerful tool, it is also one of the easier tools to misuse. Four common failure modes:



    


  1. Using the observed interim effect for θ. This replaces noise with itself, giving a CP estimate that is biased toward 0.5 and a sample size that swings with random variation. Kunzmann et al. (2022) show the variance inflation can dwarf the power gain.
    2. 





    


  1. Re-estimating outside the promising zone. In the unfavorable zone you throw money at a dying trial; in the favorable zone you add patients the trial does not need.
    2. 





    


  1. Lack of pre-specification. If the SSR rule is not in the protocol before unblinding, regulators treat the final p-value as suspect. The rule should be a fixed function of the interim Z, not a committee decision.
    2. 





    


  1. Ignoring combination tests. Using a naive final Z after adapting N inflates the Type I error rate, sometimes by a factor of 2 or more at extreme adaptations.
    2. 





Warning
An SSR rule decided after looking at interim data is not an adaptive design. It is post-hoc cherry-picking with extra steps, and it invalidates the p-value at the final analysis. Pre-specify or do not adapt.

RNaive SSR inflates alpha solution

    
set.seed(404)
B <- 5000
rejects <- replicate(B, {
  z1 <- rnorm(1, 0, 1)
  theta_hat <- max(z1 / sqrt(16), 0.05)
  n2 <- min((qnorm(0.975) + qnorm(0.80))^2 / theta_hat^2 - 16, 500)
  n2 <- max(n2, 16)
  z2 <- rnorm(1, 0, 1)
  (z1 * sqrt(16) + z2 * sqrt(n2 / 4)) / sqrt(16 + n2 / 4) > qnorm(0.975)
})

Explanation: A naive z test after observed-effect SSR pushes the empirical Type I error to about 4%, well above the 2.5% nominal. Switching the final test to z2NC restores α.

Complete Example



A sponsor is planning an oncology trial anticipating a hazard ratio of 0.70 (log-HR θ ≈ -0.357). Fixed-sample analysis requires ~290 events for 90% power at α = 0.025 one-sided. The protocol pre-specifies an unblinded interim at 50% of events with a promising-zone SSR rule.




  

    
REnd-to-end oncology SSR workflow

    
# 1. Fixed-sample anchor: plan for 290 events
# 2. Two-stage design, interim at 50% information
onc_design <- gsDesign(k = 2, n.fix = 290, timing = 0.5,
                       alpha = 0.025, beta = 0.10, test.type = 1)
onc_design$n.I
#> [1] 152.79 305.58

# 3. Suppose interim log-rank gives Z1 = 1.35 -> promising zone
onc_z1 <- 1.35
onc_ssr <- ssrCP(x = onc_design, z1 = onc_z1, maxinc = 1.75,
                 cpadj = c(0.3, 0.8), beta = 0.10, z2 = z2NC)
onc_ssr$dat
#>     z1       z2       n2    CP  theta  delta
#> 1 1.35 1.255... ~257.8 0.678  0.188  0.188

# 4. Re-estimated total events
total_events <- onc_design$n.I[1] + onc_ssr$dat$n2
round(total_events, 1)
#> [1] 410.6

# 5. At final analysis, observed stage-2 Z = 1.4
#    Combined via z2NC:
z_final <- (onc_z1 + 1.4) / sqrt(2)
z_final > qnorm(0.975)
#> [1] TRUE   # reject H0

    

      
      
    

    

  

  





The interim put the trial in the promising zone, so ssrCP() scaled up stage-2 events from 153 to about 258 (~1.7×). The inverse-normal combination at the end combines Z1 = 1.35 and Z2 = 1.4 into 1.945, just above 1.96, and the trial rejects H0. Had we used a naive final Z on the adapted data, the Type I error would not have been controlled.
